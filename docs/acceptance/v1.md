## 3. Declared divergences

A divergence is **declared** when a corpus line disagrees with PostgreSQL and the test says so in
words, with the reason. The harness fails on any disagreement that is *not* declared, so this list
is complete by construction — nothing diverges silently.

| | count |
|---|---:|
| **answers** — a value or an error differs | **427** |
| **types** — the value agrees and the column's type OID does not | **464** |

They fall into a small number of rules. Each row below is a rule, not a line; the counts are of
declared entries citing it.

| Area | Divergence | Source | Why |
|---|---|---|---|
| catalog | a `pg_catalog`/`information_schema` column is `text` where PostgreSQL has `name`, `"char"` or `character varying(3)` | the `types` list of ~most corpora (464 entries) | the characters agree; only the type OID differs, and no client reads the OID of a catalog column |
| type surface | the node stores six types and four array types, not PostgreSQL's full set | [ADR 0033](../adr/0033-tier-1-of-the-type-surface.md), [ADR 0047](../adr/0047-an-array-is-a-column-type-over-one-element-type.md) — 19 and 7 citations | a type nothing in the suite stores is `0A000` naming itself rather than approximated |
| C2 refusals | a construct that is parsed and not implemented answers `0A000` **naming itself** | contract C2; ~106 declared entries say so | a named refusal is a work item; a syntax error about valid SQL is a bug report against the wrong thing |
| deparser | `pg_get_viewdef`, `pg_views.definition` and `information_schema.columns.generation_expression` return the **stored text**; PostgreSQL returns its own re-render | [ADR 0060](../adr/0060-a-using-clause-is-a-licence-not-an-expression.md) and `pg19_view.txt`, `pg19_virtual_generated_column.txt` | reproducing `ruleutils.c` buys formatting, not meaning; the expression and its values agree |
| schema change | an index is `SchemaState::Public` from its first statement, so a staged backfill is not observable | [ADR 0020](../adr/0020-online-schema-change.md), 5 citations | the lease and the states exist; what is not built is the *staging* of every DDL through them |
| rows | a dropped column keeps its slot and reads as a tombstone | [ADR 0051](../adr/0051-a-dropped-column-keeps-its-slot.md) | a row is decoded by position, so removing a slot would misread every row written before |
| generated columns | a `VIRTUAL` generated column is **computed and stored**; `attgenerated` still answers `v` | `pg19_virtual_generated_column.txt` | measured: the two kinds differ in that one catalog column and nothing else |
| sequences | `last_value` reports the reserved block's end, not the last value handed out | `catalog::SEQUENCE_BATCH`, `pg19_add_column_not_null.txt` | a session reserves a batch, which is what makes `nextval` one write per batch; the values handed out agree |
| sequences | `nextval` and `TRUNCATE … RESTART IDENTITY` are **non-transactional** | `pg19_add_column_not_null.txt` | PostgreSQL's `nextval` is too; the restart inherits it because it writes in the same out-of-band transaction |
| numbers | float and numeric formatting and rounding differ in named cases | ~20 declared entries | each is measured and named where it differs, including that `numeric` rounds half away from zero and float rounds half to even |
| session | three entries concern the session clock or timezone | 3 declared entries | timestamps come from the statement, not a wall clock (invariant 6) |
| views | `INSERT` through an updatable view, a view following a column rename, and `pg_attribute` rows for a view | `pg19_view.txt` | all three are one missing step — resolving a view's body to ordinals at `CREATE VIEW` |
| DO | `DO` runs **two recognised templates**, not PL/pgSQL | [ADR 0058](../adr/0058-a-do-block-is-two-templates-not-a-language.md) | all 36 `DO` statements the suite sends are those two; anything else is `0A000` |
| ALTER | a `USING` clause is a **licence**, not an expression to evaluate | [ADR 0060](../adr/0060-a-using-clause-is-a-licence-not-an-expression.md) | there is no per-row expression evaluator; `USING string_to_array(…)` stays refused |

ADRs cited from inside divergence lists: 0020, 0030, 0031, 0033, 0040, 0042, 0046, 0047, 0048,
0049, 0050, 0051, 0052, 0053, 0054, 0057. ADRs cited from corpus headers: 0020, 0022, 0031, 0033,
0042, 0050, 0053, 0054.

> **[ADR 0031](../adr/0031-rails-compatibility-is-measured.md) governs this table.** Rule
> 2: an entry that starts agreeing is **deleted**, not left. Rule 3: a wrong answer is a bug, not
> an exclusion — several entries here were once refusals and became wrong answers when the refusal
> was implemented, and each was then fixed rather than re-declared.

`cargo nextest run --workspace --all-features` is **3,286 tests, 39 skipped** and green on the
merged tree (at this commit, over main `8d3ae82c`); the skips are `#[ignore]`d long runs, not failures.

| Test | Status | Evidence |
|---|---|---|
| `esker-sql::join_cost::a_materialised_join_costs_what_it_pairs_and_not_the_cross_product` | **open, unexplained** | failed once in a full 3,281-test parallel run; passed 3/3 in isolation and on the next full run. A timing-*ratio* test with a control, so load-sensitive by construction |
| `esker-store::snapshot::a_placed_columnar_learner_holds_what_the_leader_holds` | **closed** — proven an artefact and fixed (`9b839ff`) | instrumented until deterministic rather than retried |
| `peer.rs`'s election pump | **closed — fixed** | `docs/plans/debt-c6.md` §727 |
| four "load-sensitive" tests | **closed** — three source bugs behind them | `docs/plans/phase-14-flakes.md`; the mitigations were what hid the bugs |

> `docs/plans/debt-c1.md` states the standing rule: *"bugs get **fixed**; \"known flake\" is not an
> end state, and a timeout constant raised without a named broken assumption is not a fix."*

The `#[ignore]`d tests are deliberate long runs, each naming its cost:
`raft_five_nodes` (thousands of seeds), `stateright_raft` (24M states, ~48 s release),
`raft_sweep` (10,000-seed acceptance), `raft_membership`, `bench_columnar` (kept out of the gate so
nobody tunes before correctness is proven), and `promotion.rs`'s kept-failing investigation test.

## 5. Dependencies

The project is 100% Rust with no crate that compiles C, C++ or assembly at any depth — enforced by
`cargo deny` (`deny.toml` bans `*-sys`, `cc`, `openssl*`, `ring`, `aws-lc-*`, `libz*`, `zstd*`) and
by a test that counts the graph.

| | |
|---|---:|
| **transitive runtime crates** | **33** |
| budget in `deny.toml` (`esker-dep-budget`) | **37** |

Source: `crates/esker-cli/tests/dep_budget.rs`, which prints
`runtime transitive crates: 33 of 37 allowed`. The budget fell from 40 to 37 when
`crossbeam-skiplist` left with `crossbeam-epoch` and `crossbeam-utils`
([ADR 0041](../adr/0041-the-in-house-arena-skiplist.md)) — so **every piece of concurrent code in
the engine is now code in this repository with a test in this repository**.

Runtime allowlist: `tokio` (network edge only), `bytes`, `thiserror`, `tracing` +
`tracing-subscriber`, `lz4_flex`. The one large exception is `sqlparser`, taken by ADR. TLS adds
nine crates and only with the `tls` feature on, which is off by default
([ADR 0055](../adr/0055-the-tls-options-across-three-surfaces-measured.md)).
