# **`regclass[]`, oid 2210** — the array of a `regclass`, against PostgreSQL 19beta1.
#
# Group 5 of r1's wire-108 baseline. `array_agg(c::regclass)` came back a scalar `text` (25) where
# a real server answers `regclass[]` (2210), and the cause was that this node had no such type:
# `regclass`'s `typarray` was a deliberate `0`, on the reasoning that "an array of a regclass is
# not a type this node offers". A client reads that number. `ActiveRecord` decides a value is an
# array from `pg_type`, and a `regclass[]` described as `text` is a Ruby String where the schema
# dumper expects a list.
#
# **Group 7 is here too**, because it is the same measurement: `min`/`max` over a `regclass`, a
# `regtype` or a `regproc` is an `oid` — value included, not just the declared type — and an array
# of any of them is not. See `tests/captures/pg19_reg_class.txt`, which also corrects ADR 0098's
# claim that a `regtype` keeps its own type here.
#
#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it
#   statement <tab> <tab> -               a command with no result set, only a tag
#   statement <tab> !SQLSTATE message     PostgreSQL refused it; DETAIL and HINT follow
#
# THINGS REASONING WOULD GET WRONG
#
#   * **2210 is not adjacent to 2205.** `_regtype` (2211) sits beside `regtype` (2206) and
#     `_regclass` does not sit beside `regclass`: the `reg*` arrays were assigned in a later
#     initdb than the scalars. Neither number is derivable from the other.
#   * **A bad name inside an array literal is the element's error, not the array's.**
#     `'{nosuchrel}'::regclass[]` is `42P01 relation "nosuchrel" does not exist` — `array_in` calls
#     `regclassin` per element — where an integer parser handed the same text would say `22P02`.
#   * **`to_regclass` is a `regclass` even when it finds nothing.** The miss is a `regclass` NULL.
#   * **`min` over a `regclass[]` keeps `regclass[]`.** An array has a `min` of its own; the three
#     scalars do not, which is why they decay and the array does not.
#   * **`'rc'::regclass::text` is still `text`.** The output function is a name and the `::text`
#     around it is a real cast now that the inner half answers 2205 — `ActiveRecord`'s
#     `foreign_keys()` reads exactly that shape.
#
# Measured in `tests/captures/pg19_reg_class.txt`.
