# THINGS REASONING WOULD GET WRONG
#
#   * **The result type is the argument's, and a `date` is not the type it looks like.** A `date`
#     resolves to the `timestamptz` overload, so `date_trunc('day', DATE '…')` is zoned; so is the
#     three-argument form even when its value is an unzoned `timestamp`.
#   * **The session `TimeZone` decides where a `timestamptz` is cut.** The same statement is
#     `2026-09-05 00:00:00+00` in UTC and `2026-09-06 00:00:00+10` in Sydney, and under
#     `America/New_York` a `month` truncation of `2026-09-01 02:00:00+00` lands in **August**.
#   * **`quarter` has no plural and no abbreviation** while every other unit takes at least one
#     alias: `months`/`mon`/`mons`, `centuries`/`cent`/`c`, `millennia`/`mil` all truncate, and
#     `quarters` and `q` are refused. `m` is the **minute**.
#   * **Two error classes.** A unit the table does not hold is `22023 … not recognized`; a unit it
#     holds that this function cannot apply is `0A000 … not supported` — `timezone` on a timestamp
#     and `week` on an interval. `epoch` and `dow` are `EXTRACT` fields and land in the *first*
#     class, which reasoning puts in the second.
#   * **A decade truncation of a 3-year interval is `00:00:00`**, not an empty interval and not
#     `0 years`.
#   * The unit is case-insensitive but **not trimmed**: `' month'` is a refusal.
