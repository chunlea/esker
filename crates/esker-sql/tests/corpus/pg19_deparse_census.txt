# **The deparse census: expression shape x reader**, measured on PostgreSQL 19beta1.
#
#!escaped
#
# Two days of run-108-shaped reds had one thing in common -- they were **wrong and green**: the
# node printed a stored expression differently from a real server and no test in this repository
# said so, because each reader had been measured on the shapes that happened to reach it. This
# file is the cross product instead: 80 expression shapes and 10 constants against the eight
# readers each admits, 211 probes, so the next parenthesis rule is learned here and not from the
# suite. Thirty-eight of the shapes were added by group A's and group E's own measurements, which
# is the census working. Group A added a four-term chain, a chain parenthesised in the middle, a
# `CASE` under an arithmetic operator, under a `NOT` and on either side of an `AND`, and an
# exclusion constraint's predicate through both of its readers. Group E added the whole no-op-cast
# family: seventeen casts through a generated column, four index keys through `pg_get_indexdef`
# *and* `pg_index.indkey`, and two `DEFAULT`s -- because eliding a cast is not a printing rule. An
# index key whose expression resolves to a bare column stops being an expression key at all, and
# only the catalog columns say so.
#
#     shapes   binary chains (AND/OR mixed and nested) * operator-spelled functions in both
#              directions * CASE searched and simple, with comparisons and functions in every
#              position * cast chains and negative constants * array constructor, subscript,
#              slice and concatenation * nested string functions * NULL tests * BETWEEN * LIKE
#              and ILIKE * IS DISTINCT FROM * IN * COALESCE/GREATEST/NULLIF
#
#     readers  pg_get_constraintdef plain and pretty * pg_get_indexdef * pg_get_expr(indexprs) *
#              pg_get_expr(indpred) * pg_get_expr(adbin) for a generated column and for a DEFAULT *
#              pg_get_viewdef
#
# **Every probe is inside its own savepoint**, and three of them earn it: PostgreSQL refuses
# `(ARRAY[...])::text` in a generated column -- `generation expression is not immutable`, because
# the array-to-text cast reads settings -- and the refusal is recorded rather than repaired, since
# a reader that refuses is as much a fact as one that prints.
#
# Captured by a `psql -At` script with a marker per probe
# (`scratchpad/census/probe.sql`), **not** by `sesscap.py`: a `CASE` read-back and a view
# definition both hold newlines, and that tool still drops every output line beginning with a
# space (`docs/plans/debts-v1.1.md` #20's second half, r1's). The values carry this format's escape
# contract, which is what makes a newline expressible at all.
