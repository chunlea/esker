# That file declares seven point columns and one **`point[]`** (`:23-30`), two of them with a
# default written as a Ruby array (`[12.2, 13.3]`) and two as a string (`"(14.4,15.5)"`), and it
# reads all four back out of the schema dumper. So the type has to store, print, default and
# array, and the name has to survive `format_type` and `information_schema`.
#
# **The fact that decides its shape: a `point` has no equality and no ordering at all.**
# `point = point` and `point < point` are each `42883 operator does not exist` — only `~=`
# (same-as) and `<->` (distance) exist — and `CREATE INDEX` on one is `42704 data type point has
# no default operator class for access method "btree"`. Under ADR 0042's rule (a type may share
# another's representation only if it shares its comparison) that makes it a **not-an-index-key**
# type, the same standing `json` has, and for a sharper reason: `json` has no equality either, and
# a point does not even have one with itself.
#
# Other things reasoning would get wrong:
#
# * **The input is looser than the output.** `'( 1 , 2 )'` and a bare `'1,2'` are both accepted
#   and all three print `(1,2)` — the parentheses are the output function's, not the parser's.
# * **The coordinates print as `float8` does**, so `1e10` is `10000000000` and `2e-10` stays
#   `2e-10`. A formatter of its own would get one of those two wrong.
# * **A subscript is a `double precision` and is zero-based** — `p[0]` and `p[1]`, not `p[1]` and
#   `p[2]`.
# * `typlen` is **16**, not -1: two `float8`s and no length header.
# * The category is **`G`** for geometric, which is neither `U` nor `S`.
#
