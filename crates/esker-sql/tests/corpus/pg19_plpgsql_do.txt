# The last line proves the session left nothing behind.
#
#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it
#   statement <tab> <tab> -               a command with no result set, only a tag
#   statement <tab> !SQLSTATE message     PostgreSQL refused it; DETAIL and HINT follow
#
# THINGS REASONING WOULD GET WRONG
#
#   * **`SELECT … INTO n` takes the first column of the first row and ignores the rest**: a
#     three-row `SELECT … INTO n` and `SELECT 1, 2 INTO n` both answer `DO`, and no row assigns
#     NULL.
#   * **An assignment converts the way PL/pgSQL does**: `n = 7.6` stores 8, `n = '7'` stores 7
#     through the text, and `n = 'abc'` is `22P02` for the integer. A `bigint` count into an
#     integer is an ordinary assignment.
#   * **`IF 1 THEN` is true**: a condition that is not a boolean is read through its text.
#   * **`EXECUTE` of one string holding two statements runs both**, a `SELECT` it runs is thrown
#     away, `EXECUTE NULL` is `22004`, and `EXECUTE 'BEGIN'` is PostgreSQL's own `0A000`.
#   * **Rows with nowhere to go are `42601`**: a `SELECT` gets a HINT naming `PERFORM`, an
#     `INSERT … RETURNING` gets the same sentence without one.
#   * **A name that is both a variable and a column is `42702`**, not silently the variable.
#   * **A malformed body answers sentences no SQL parser writes**: `missing "THEN" at end of SQL
#     expression` when a `;` comes first and `syntax error at end of input` when the body ends
#     first; `unexpected end of function definition at end of input` for a statement cut off.
#   * **`RAISE WARNING 'a', 'b'` is `42601 too many parameters specified for RAISE`**, while
#     `RAISE WARNING 'a %', 'b'` runs.
#   * **An error part-way through a block undoes the block**: the row inserted before a duplicate
#     key is not there afterwards.
