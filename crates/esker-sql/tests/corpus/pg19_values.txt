# What a real PostgreSQL 19beta1 does with a value -- contract C3's gate for the six types
# phase 6a stores (docs/plans/phase-6a.md §1, §6).
#
# Nothing here was written from the documentation. Every line was produced by putting the input
# text to a running PostgreSQL 19beta1 as `SELECT $ek$<input>$ek$::<type>` -- dollar-quoted, so
# the bytes the server's input function saw are exactly the bytes in this file -- and recording
# either what its output function printed or the SQLSTATE and message it refused with.
#
#   type <tab> input <tab> output          the value, as PostgreSQL prints it in a text DataRow
#   type <tab> input <tab> !SQLSTATE msg   PostgreSQL refused the input
#
# `\\` is one backslash, `\t` a tab, `\n` a newline, and `\N` on its own is SQL NULL. A `#` at
# the start of a line is a comment and a blank line is ignored.
#
# The output column is the *output function's* result, not a `::text` cast: `true::text` is
# `true` but a boolean on the wire is `t`, and capturing the cast would have taught us the wrong
# format for the one type where the two differ.
#
# tests/value_parity.rs reads this file and requires our own input and output functions to agree
# with it, holding the divergences we accept from both sides.
