# `tsrange` — the five range values `range_test.rb` inserts, and how they come back.
#
# **Run 50 ranking: `the type tsrange is not supported`, 46 tests in one file**
# (`adapters/postgresql/range_test.rb`). That file declares eight range columns; `tsrange` is the one
# the board names because it is the first the node refuses, and `t.tsrange :ts_ranges, array: true`
# means the array form is in the same table.
#
# The five rows below are the file's own fixtures (`insert_range(id: 101…105)`), in its order:
# closed `[a,b]`, half-open `[a,b)`, unbounded-above `[a,]`, infinite, and empty.
#
# Things reasoning would get wrong:
#
# * **A timestamp range is NOT canonicalised.** `int4range '[1,10]'` comes back `[1,11)` because the
#   subtype is discrete; `tsrange '[a,b]'` comes back exactly `["a","b"]`, because a timestamp has no
#   successor function. Both are in the rows below, side by side, because an implementation that
#   canonicalises everything or nothing is wrong either way.
# * **The bound characters are data.** `[`, `]`, `(`, `)` and the empty slot after a comma survive the
#   round trip and `lower_inc`/`upper_inc`/`lower_inf`/`upper_inf` read them back.
# * **`'empty'` is a value, not NULL**, and it is not the same as `NULL`: `isempty` is `t` for one and
#   the whole value is NULL for the other. `range_test.rb` asserts both, separately.
# * **The text output depends on `DateStyle`**, the way `pg19_date.txt` records for `date` — and AR
#   sets `intervalstyle` but not `DateStyle`, so the server default is what it reads.
# * **`test_escaped_tsrange` uses year -1000**, which PostgreSQL renders `1000-01-01 … BC`. A parser
#   that assumes four digits and no suffix fails that test and nothing else.
#
# **Re-captured from r1's `captures/pg19_tsrange.txt`, statement for statement**, with the three
# catalog probes at the top moved into `SAVEPOINT`s: `current_setting('DateStyle')`, `pg_range` and
# the `pg_type` row are none of them built here, and run bare the first `42704` aborted the replay
# and took the forty-six statements after it — which are the whole file. Every answer is
# byte-identical to r1's.
#
# The whole capture runs inside `BEGIN … ROLLBACK`; error probes sit in `SAVEPOINT`/`ROLLBACK TO`,
# and the `SELECT count(*)` after the `ROLLBACK` proves it left nothing behind. `\gdesc` runs in a
# second session after that rollback, so statements naming `tsr` have an **empty** declared-types
# column; the `pg_typeof` lines pin the types instead.
#
