# `bit(n)` and `bit varying(n)` — against PostgreSQL 19beta1.
#
# **Run 71's `type "…" does not exist` row: 6 tests in `bit_string_test.rb`**, whose `setup`
# declares four columns — `bit(8)` and `bit varying(4)` with defaults, and a bare one of each.
#
# Things reasoning would get wrong:
#
# * **`bit` and `bit varying` are one representation and two types**: `B'101'::bit varying =
#   B'101'::bit(3)` is `t`, so ADR 0042 allows the sharing, and the value carries which it is.
# * **A cast pads on the right and an assignment refuses.** `'101'::bit(8)` is `10100000` — the
#   padding is on the *right*, which is the half a reader gets wrong — and `'101010101'::bit(4)`
#   is `1010`, while the same values assigned to a column are `22026 bit string length 3 does not
#   match type bit(8)` and `22001 bit string too long for type bit varying(4)`.
# * **A bare `bit` column is `bit(1)`** and a bare `bit varying` has no length at all.
# * **`0xF` is not a bit string.** `'0xF'::bit(4)` is `22P02 "x" is not a valid binary digit` — the
#   message names the *character*, not the type — and the hexadecimal form is the literal `x'F'`,
#   which is `1111`. `bit_string_test.rb`'s `"0xF"` is converted by `ActiveRecord` before the
#   statement is built; the server never sees it.
# * **`typcategory` is `V`**, a category of its own, and `typname` for the varying one is
#   `varbit`. The default reads back `'00000011'::"bit"` — quoted, because `bit` is reserved.
# * `min(bit)` does not exist; `bit = text` is `42883`.
