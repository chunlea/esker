# `~`, `~*`, `!~`, `!~*` — POSIX regular-expression matching — as a real PostgreSQL 19beta1
# answers it.
#
# **`ActiveRecord`'s PostgreSQL adapter sends exactly four patterns**, and they are the whole
# reason this exists:
#
#     schema_names          nspname !~ '^pg_.*'
#     pk_and_sequence_for   pg_get_expr(…) ~* 'nextval|uuid_generate|gen_random_uuid'
#     pk_and_sequence_for   pg_get_expr(…) !~* 'nextval'
#     pk_and_sequence_for   split_part(…, '''', 2) ~ '.'
#
# Between them: an anchor, `.`, `*`, alternation, and all four operators. The first is the opening
# statement of `schema_names`, which is why `pg19_schema.txt` loses sixty-two statements behind it,
# and the other three are on the path every model takes at boot.
#
# **No regex crate.** `deny.toml` forbids one, and the matcher is written in-house for the POSIX
# ERE subset these need and a little around it — literals, `.`, character classes with ranges and
# `[[:name:]]`, `^`/`$`, alternation, grouping, `*`, `+`, `?`, `{m}`/`{m,n}`, and `\` escapes.
# Anything outside that subset is refused by name (ADR 0031) and is declared here.
#
# Captured in one session with `scratchpad/sesscap.py` and replayed the same way.
#
# **The whole capture runs inside `BEGIN … ROLLBACK`**, error probes in `SAVEPOINT` / `ROLLBACK TO`.
# The `SELECT count(*)` at the end proves it left nothing behind and answers `0`. `\gdesc` runs
# inline, so every statement has its declared types pinned.
#
#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it
#   statement <tab> <tab> -               a command with no result set, only a tag
#   statement <tab> !SQLSTATE message     PostgreSQL refused it; DETAIL and HINT follow
#
# THINGS REASONING WOULD GET WRONG
#
#   * **`.` matches a newline.** `E'a\nb' ~ '^a.b$'` is **true**. Almost every regex engine outside
#     POSIX makes `.` stop at a newline, and an implementation that copied one would answer `f`
#     where a real server answers `t`.
#   * **The empty pattern matches everything**: `'abc' ~ ''` is `t` and `'abc' !~ ''` is `f`. A
#     matcher that treated an empty pattern as "no match" would invert both.
#   * **A pattern is unanchored**: `~` is a *search*, not a full match, so `'abc' ~ 'b'` is true and
#     `'^abc$'` is what makes it whole-string. The suite's `'^pg_.*'` is anchored at the front only,
#     and `.*` at the end is therefore doing nothing at all — `'^pg_'` would answer identically.
#   * **NULL on either side is NULL, for all four operators**, and the negated ones do not rescue
#     it: `'abc' !~ NULL` is NULL, not true.
#   * **`]` first inside a class is a literal**: `'a]b' ~ '^a[]]b$'` is true. `[]]` is a class
#     containing `]`, not an empty class followed by `]`.
#   * **`\a` is not `a`.** `'a' ~ '^\a$'` is **false** — a backslash before an ordinary letter is an
#     escape PostgreSQL gives its own meaning (`\a` is the alert character), so escaping is not
#     "drop the backslash". `\.` and `\*` do work, and are what a pattern needs them for.
#   * **Bounds are in the subset**: `'foo' ~ 'o{2}'` is true, `'fo' ~ 'o{2}'` is false, and
#     `'^fo{1,2}$'` matches `foo`.
#   * **Three different `2201B` reasons, and the sentence names which**: `brackets [] not balanced`,
#     `parentheses () not balanced`, `quantifier operand invalid`. One code, three messages.
#   * **A non-text operand is `42883`, not a cast**: `1 ~ 'a'` is `operator does not exist: integer
#     ~ unknown` with PostgreSQL's DETAIL and HINT, and `'abc' ~ 1` is the same sentence with the
#     sides swapped — `unknown ~ integer`.
#   * **`~*` folds both sides, and `!~*` is its negation**: `'ABC' ~* 'b'` is true while `'ABC' ~ 'b'`
#     is false, and the suite's `~* 'nextval|…'` is why — a default of `nextval('s'::regclass)`
#     matches whatever case it was written in.
#
# OUTSIDE THE SUBSET, AND DECLARED
#
#   * `(?i)` and the rest of PostgreSQL's *advanced* regular expressions, which are not POSIX ERE.
#   * Back-references (`\1`). Both are captured here so the boundary is written down rather than
#     merely absent, and both are refused by name.
