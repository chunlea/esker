# `INSERT … ON CONFLICT` — `DO NOTHING`, `DO UPDATE`, `excluded`, and what all three do through a
# **partitioned** parent — as a real PostgreSQL 19beta1 answers it.
#
# This is what `insert_all` and `upsert_all` compile to. The shapes are `ActiveRecord`'s own, out
# of `connection_adapters/postgresql_adapter.rb#build_insert_sql`:
#
#     ON CONFLICT #{conflict_target} DO NOTHING
#     ON CONFLICT #{conflict_target} DO UPDATE SET <col>=excluded.<col>, …
#     … RETURNING <cols>
#
# `conflict_target` is `(cols)`, optionally with the arbiter index's `WHERE`, and is **empty** for
# `insert_all` with no `unique_by` — which is where the double space in the third line comes from.
# `pg19_partition_suite.txt` declared this statement a divergence; this closes it.
#
# Captured in one session with `scratchpad/sesscap.py` and replayed the same way.
#
# **The whole capture runs inside `BEGIN … ROLLBACK`**, error probes in `SAVEPOINT` / `ROLLBACK TO`.
# The `SELECT count(*)` at the end proves it left nothing behind and answers `0`. `\gdesc` runs
# inline, so every statement has its declared types pinned.
#
#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it
#   statement <tab> <tab> -               a command with no result set, only a tag
#   statement <tab> !SQLSTATE message     PostgreSQL refused it; DETAIL and HINT follow
#
# THINGS REASONING WOULD GET WRONG
#
#   * **The sequence is consumed for a row that is never inserted.** Three inserts of `isbn` `2`
#     and `3` come back with ids `5`, `5`, `7`: the second drew `6` from `books_id_seq`, conflicted,
#     updated the row that already had `5`, and returned **`5`** — and `6` is gone. `nextval` is
#     evaluated to build the proposed row, before anything knows there is a conflict, and it does
#     not roll back. An implementation that allocated after the conflict check would answer `6`
#     and would never leave a gap.
#   * **`DO UPDATE SET "id"=excluded."id"` writes the number that was drawn**, which is how you can
#     see it: the row's `id` becomes `13`, a value no `INSERT` ever returned.
#   * **`RETURNING` answers only the rows the statement actually touched.** `DO NOTHING RETURNING
#     "id"` on a row that conflicts returns **no rows at all** — not a NULL, not the existing id.
#     `DO UPDATE … RETURNING "id"` returns the **existing** row's id, because that is the row it
#     wrote.
#   * **Two proposed rows that conflict with each other are two different answers.** With
#     `DO UPDATE` it is `21000 ON CONFLICT DO UPDATE command cannot affect row a second time`
#     (`HINT: Ensure that no rows proposed for insertion within the same command have duplicate
#     constrained values.`); with `DO NOTHING` it is accepted and the **first** of the two wins.
#   * **The conflict target has to match an index, not a column.** `ON CONFLICT ("name")` where
#     `name` has no unique index is `42P10 there is no unique or exclusion constraint matching the
#     ON CONFLICT specification`, and a **partial** index only matches when the statement repeats
#     its predicate: `ON CONFLICT ("a") WHERE "b" IS NOT NULL` works where bare `ON CONFLICT ("a")`
#     is `42P10`.
#   * **Three columns, three messages.** A target naming nothing is `42703 column "nosuchcol" does
#     not exist`, quoted; an `excluded` column naming nothing is `42703 column excluded.nosuchcol
#     does not exist`, **unquoted and qualified**; and the target table may be named in the `SET`
#     (`"name"="books"."name"`), where it means the row already there.
#   * **`ON CONFLICT` with no target at all takes any unique index.** `ON CONFLICT  DO NOTHING` —
#     `insert_all`'s spelling, with the double space `build_insert_sql` leaves — skips the row.
#
# THROUGH A PARTITIONED PARENT
#
#   * **The conflict is routed first and arbitrated second.** `upsert_all` through `measurements`
#     updates the row in whichever partition holds it and inserts the rest where they belong: one
#     row in `measurements_toronto`, two in `measurements_concepcion`, from one statement. Sent
#     straight into `measurements_toronto` it arbitrates on that partition's own index.
#   * **Routing wins over `DO NOTHING`.** A row no partition takes is `23514 no partition of
#     relation "measurements" found for row` even with `ON CONFLICT … DO NOTHING` — the clause
#     never gets a chance, because there is no partition whose index could arbitrate.
#   * **`DO UPDATE` cannot move a row between partitions, where a plain `UPDATE` can.** Setting the
#     key to the value it already has is fine; setting it to another partition's value is
#     `0A000 invalid ON UPDATE specification`, `DETAIL: The result tuple would appear in a different
#     partition than the original tuple.` `UPDATE measurements SET city_id = '2'` moves the row and
#     raises nothing (`pg19_partition.txt`), so the two paths differ on exactly this.
