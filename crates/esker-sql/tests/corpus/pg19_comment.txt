# `COMMENT ON` and the two functions that read it back, as PostgreSQL 19beta1 answers them.
#
# `ActiveRecord` writes a table's and a column's comment into its schema dump and reads them with
# `obj_description(c.oid, 'pg_class')` and `col_description(a.attrelid, a.attnum)` — boot
# statements 29 and 32, and the two joins those live in are in this file verbatim.
#
#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it
#   statement <tab> <tab> -               a command with no result set, only a tag
#   statement <tab> !SQLSTATE message     PostgreSQL refused it; DETAIL and HINT follow
#
# Captured in one session inside `BEGIN … ROLLBACK`, in this order, so the state each line sees is
# the state the line above left. Nothing was left on the oracle.
#
# THINGS REASONING WOULD GET WRONG
#
#   * **A table's comment and its columns' comments are separate rows.** `COMMENT ON TABLE t IS
#     NULL` removes the table's and leaves every column's — measured on the line after it.
#   * **`col_description(oid, 0)` returns the TABLE's comment.** `pg_description` keys a table
#     comment as `objsubid = 0` and the function does not special-case it. Attnum 0 is the one
#     subscript that is neither out of range nor a column.
#   * **`IS ''` is the same as `IS NULL`** — the row is deleted rather than an empty comment
#     stored, so a comment that *is* the empty string cannot be observed.
#   * **A comment is keyed by the object, not by its name**: it survives `ALTER TABLE … RENAME TO`
#     and `RENAME COLUMN`, and it dies with `DROP COLUMN`, `DROP INDEX` and `DROP TABLE`. An index
#     dropped and recreated under the same name has no comment: it is a different index.
#   * **The wrong object kind is `42809`, not `42P01`**: `COMMENT ON INDEX <a table>` is
#     `"cm" is not an index`, and the message names the kind that was asked for.
#   * A missing relation is `42P01` and a missing column is `42703` naming both — the messages a
#     real server raises for them anywhere else.
