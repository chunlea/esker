# The `ActiveRecord` schema-dump path, statement for statement -- phase 13 unit 5.
#
# The acceptance for this phase. Every statement `schema_dumper`, `indexes()`, `foreign_keys()`,
# `columns()` and `primary_keys()` send, **verbatim from `activerecord-8.1.3.1`**
# (`connection_adapters/postgresql/schema_statements.rb` and `postgresql_adapter.rb`), over a
# fixture schema of this node's own types, put to both servers.
#
# Where a statement carries a piece of SQL this node has no feature for -- `ARRAY(SELECT ...)`,
# `array_agg`, `generate_subscripts`, `col_description`, `obj_description`, `oid::regclass::text` --
# the *rest* of it is here and the piece is named in the divergence list. That is the point of
# putting the real statements rather than a paraphrase: what is missing is a clause, not a row, and
# the rows behind every one of them agree.
#
# Captured in one session with `scratchpad/sesscap.py` inside one `BEGIN ... ROLLBACK`, and
# replayed the same way against one node.
#
#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it
#   statement <tab> <tab> -               a command with no result set, only a tag
#   statement <tab> !SQLSTATE message     PostgreSQL refused it; DETAIL and HINT follow
#
# WHAT THIS PINS THAT NO EARLIER UNIT COULD
#
#   * **The oid joins, three deep.** `pg_class t -> pg_index d -> pg_class i` in one statement, with
#     `pg_namespace` on the side. Every unit before this asserted rows; this asserts that the rows
#     *join*, which is the thing two views computed independently would get wrong.
#   * **`columns()` over eighteen columns of fourteen types**, with `format_type` reading each
#     column's own `atttypid` and `atttypmod` rather than a literal: `character varying(1024)` from
#     a typmod of 1028, `character(3)` from 7, `timestamp(3) without time zone` from 3, and
#     `character varying` bare from -1.
#   * **A `bigserial`'s default read back through the join it arrives by**:
#     `nextval('dumpy_id_seq'::regclass)` out of a `LEFT JOIN pg_attrdef`, beside seventeen columns
#     whose `pg_get_expr` is NULL because the join matched nothing.
#   * **`indisvalid`, `indisunique` and `indkey` for two indexes at once**, and `indkey` `7 8` --
#     the attnums of the seventh and eighth columns, which is the number that was wrong when it was
#     read off the wrong list.
