# Arithmetic over the date and time types, as a real PostgreSQL 19beta1 answers.
#
# The table is not a promotion and almost none of it is derivable from the rest:
#
#   * **`date - date` is an `integer`** — a count of days — where `timestamp - timestamp` and
#     `time - time` are `interval`s;
#   * `date + integer` is a `date` and `date + interval` is a **`timestamp`**;
#   * `time * 2` is an **`interval`**, because twenty-four hours is not a time of day;
#   * `date + numeric` has no operator at all: `42883`, not a refusal.
#
# And four rules about the values:
#
#   * **an interval's three fields never carry into each other.** `'25 hours' + '1 day'` is
#     `1 day 25:00:00` and `'1.5 days' * 2` is `2 days 24:00:00`. Carrying would change the
#     meaning: a day is not always 24 hours and a month is not a fixed number of days;
#   * **a month lands on the last day it can, and forgets where it came from.**
#     `'2020-01-31' + '1 month'` is `2020-02-29`, and another month gives `2020-03-29` — so month
#     addition is not associative;
#   * **a time wraps and drops the days.** `'23:00' + '2 hours'` is `01:00` and `'12:00' + '1 day'`
#     is `12:00`;
#   * **`-time` is an `interval`** while `-date` and `-timestamp` are `42883` with PostgreSQL's
#     *unary* wording — one operand, so its `DETAIL` and `HINT` are singular where the binary
#     form's are plural. An instant has no negative and a duration does.
#
# The two failures are their own sentences rather than overflows: `'infinity'::date - <date>` is
# `22008 cannot subtract infinite dates`, and a shift past the type's ends is `22008 date out of
# range`. An infinite date **absorbs** a shift: `'infinity'::date + 1` is `infinity`.

SELECT '2020-01-01'::date + 7	date	2020-01-08
