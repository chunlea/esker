# `ltree` — against PostgreSQL 19beta1.
#
# **Run 70's row: 4 tests in `adapters/postgresql/ltree_test.rb`.** One extension, one column
# (`t.ltree "path"`), a round trip and a schema dump.
#
# Things reasoning would get wrong:
#
# * **The order is not the text's.** `'a.b'::ltree < 'a-b'::ltree` is `t` and `'a.b' < 'a-b'` as
#   bytes is `f`: a real server compares label by label, and a `.` (0x2E) sits above a `-` (0x2D).
#   Equality *is* the text's, so this is ADR 0042 with only half of it failing — the type may share
#   `text`'s row representation and may not share its key.
# * **Its refusal is a *syntax* error**: `42601 ltree syntax error at character N`, one-based, not
#   the `22P02` every other input function gives. A trailing separator has no character to point
#   at and says `DETAIL: Unexpected end of input.` instead.
# * **A label is `A-Za-z0-9_-` or a non-ASCII letter** — `héllo` is a path, `a b` and `a@b` are
#   not — and the **empty path** is a value with zero labels.
# * **`min(ltree)` does not exist** even though the type is fully ordered and indexable, which is
#   the list ADR 0031 turned into a rule, one type longer.
