# `information_schema`, as a real PostgreSQL 19beta1 answers it -- phase 13 unit 4.
#
# The SQL standard's view of the same records `pg_catalog` describes. Five relations, and two of
# them answer a question `pg_catalog` cannot answer on this node at all: `key_column_usage` gives a
# primary key's columns **one row each**, where `pg_index.indkey` gives them as an `int2vector`
# that needs `= ANY` over an array value to read.
#
# Captured in one session with `scratchpad/sesscap.py` inside one `BEGIN ... ROLLBACK`, and
# replayed the same way against one node. The corpus builds its own tables.
#
#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it
#   statement <tab> <tab> -               a command with no result set, only a tag
#   statement <tab> !SQLSTATE message     PostgreSQL refused it; DETAIL and HINT follow
#
# THINGS REASONING WOULD GET WRONG
#
#   * **Only tables are in it.** An index, a sequence and a primary key are all in `pg_class` and
#     none of them is in `information_schema.tables` or `.columns` -- `count(*)` is 0 for each of
#     the three, measured one at a time.
#   * **A `NOT NULL` is reported as a `CHECK`.** `table_constraints` reads `pg_constraint`, and
#     PostgreSQL 19's `contype` `n` rows come out with `constraint_type` **CHECK** -- so
#     `sb (id int8 PRIMARY KEY, x int4 NOT NULL, ...)` has three rows here, two of them CHECK, and
#     a `constraint_type = 'CHECK'` filter returns two constraints on a table with no `CHECK` in
#     its DDL.
#   * **`is_nullable` and `is_identity` are `YES`/`NO`**, the standard's `yes_or_no` domain, and
#     not booleans. A client reading them as booleans reads every column as true.
#   * **An integer's `numeric_scale` is 0 and a float's is NULL.** `bigint` is 64/0, `integer` is
#     32/0, `smallint` is 16/0, `double precision` is 53/NULL and `real` is 24/NULL.
#   * **`datetime_precision` is 6 for a `timestamp` with no declared precision**, not NULL -- the
#     number of fractional digits it stores -- while `character_maximum_length` for a `varchar`
#     with no length *is* NULL. Two "no modifier" cases, two different answers.
#   * **`udt_name` is the internal name and `data_type` is the spelled one**: `varchar` against
#     `character varying`, `bpchar` against `character`, `timestamptz` against
#     `timestamp with time zone`.
#   * **A `bigserial` column is `is_identity NO`** with the `nextval` in `column_default`, where a
#     `GENERATED ... AS IDENTITY` column is `is_identity YES` with `column_default` NULL. Both are
#     `is_generated NEVER` -- that column is about `GENERATED ... AS (expr)` and neither is one.
#   * **`referential_constraints` is empty here even on a real server** for a schema with no
#     foreign keys, which is why an empty answer is a correct one rather than a gap.
#   * **A write to `information_schema` is refused as a *view*, not as a permission.** `DROP TABLE
#     information_schema.tables` is `42809 "tables" is not a table` with
#     `HINT: Use DROP VIEW to remove a view.`, where `DROP TABLE pg_catalog.pg_class` is
#     `42501 permission denied`. Two neighbouring schemas, two refusals -- because
#     `information_schema` really is built out of views and `pg_catalog` out of tables. And a bare
#     `DROP TABLE tables` is `42P01`, which is the same answer as reading one.
