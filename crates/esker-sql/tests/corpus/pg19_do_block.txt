# THINGS REASONING WOULD GET WRONG
#
#   * **A `DO` block returns no result set at all** — not an empty one, not a count. It is a
#     command tag, and `create_enum` runs it through `internal_exec_query`, which must tolerate that.
#   * **It is a statement, not an expression.** `SELECT DO $$ … $$` is `42601 syntax error at or
#     near "DO"`. There is no value to select.
#   * **The body really executes and its effects persist.** `DO $$ BEGIN CREATE TABLE do_made_this
#     (a int); END $$` leaves the table behind — so a `DO` block is not a no-op that can be skipped,
#     and the idempotent-enum block genuinely creates the type on the first run and genuinely does
#     nothing on the second (`count(*)` stays `1`).
#   * **`RAISE EXCEPTION` inside it surfaces as `P0001` with the raised text as the whole message** —
#     `!P0001 boom`, no DETAIL, no function name.
#   * **A syntax error in the body is reported at `CREATE`/execute time, not at parse time of the
#     outer statement**: `DO $$ BEGIN SELECT 1 END $$` is
#     `42601 unexpected end of function definition at end of input` — a plpgsql message, not a
#     SQL-parser one, so the body has to be parsed by something that understands plpgsql.
#   * **`LANGUAGE` is optional and defaults to plpgsql**, may be written *before* the body
#     (`DO LANGUAGE plpgsql $$ … $$`) or after it, and an unknown one is `42704 language
#     "nosuchlang" does not exist`.
#   * **The dollar-quote tag is arbitrary**: `$do$ … $do$` works identically to `$$ … $$`, and the
#     body may contain `;` freely — which is why this statement cannot be split on semicolons.
