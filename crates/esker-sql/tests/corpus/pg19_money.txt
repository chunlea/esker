# `money` — cents in an `i64`, against PostgreSQL 19beta1 with `lc_monetary = 'C'`.
#
# **Run 59's tier-3 row: 12 tests in `adapters/postgresql/money_test.rb`**, whose `setup` sets
# `lc_monetary` and declares `t.money "wealth"` and `t.money "depth", default: "150.55"`.
#
# Things reasoning would get wrong:
#
# * **The type is an integer.** `typlen` is 8 and `typstorage` is `p` — plain, not a varlena — so
#   the range is exactly `i64`'s in hundredths: `$92,233,720,368,547,758.07` is the top and one
#   cent more is `22003`. Both ends are in the corpus.
# * **The input is far looser than the output.** `$`, thousands separators and *brackets* are all
#   accepted — `(1.00)` is `-$1.00`, the accountants' minus — and `.12` is `$0.12` while `1` is
#   `$1.00`. What comes back is always `$`, separators and two decimals.
# * **Input rounding is half away from zero**, and it takes four consecutive half-cents to say so:
#   `.855` → `.86`, `.865` → `.87`, `.875` → `.88`, `.885` → `.89`. Half-to-even would give two of
#   those differently.
# * **Arithmetic rounds the other way.** `money * float`, `money * numeric`, `money / float` and
#   `money / numeric` all round **half to even** — `$0.05 * 0.5` is `$0.02` and `$0.15 * 0.5` is
#   `$0.08` — while **`money / integer` truncates**: `$2.00 / 3` is `$0.66`, where `$2.00 /
#   3::numeric` is `$0.67`. Three rules, each probed four times.
# * **The operator set is not a promotion ladder.** `money * 2` is a money, `money * money` is
#   `42883`, `money / money` is a **`double precision`**, `3 * money` works and `3 / money` does
#   not, and `money + 1`, `money = 1.00` and `avg(money)` are each `42883`.
# * **`sum(money)` stays a money** and is the one `sum` that can overflow: an `int8` widens to
#   `numeric` on a real server precisely so that it cannot.
# * **The casts are asymmetric.** `numeric::money` and `int::money` work, `money::numeric` works,
#   and `float8::money`, `money::float8` and `money::int8` are each `42846`. A value that is cents
#   does not travel through a float in either direction.
# * **`information_schema` reports no precision and no scale.** Both are NULL for a money column;
#   the `scale: 2` `ActiveRecord`'s schema dumper prints is the adapter's own constant. The default
#   comes back as `'$150.55'::money`, symbol and cast included, which is what that dumper reads.
#
