# **`FOREIGN KEY`, enforced** — statement 52 of `schema.rb`, and everything behind it
#
# `ALTER TABLE "authors" ADD CONSTRAINT "fk_rails_94423a17a3" FOREIGN KEY ("author_address_id")
# REFERENCES "author_addresses" ("id") DEFERRABLE INITIALLY IMMEDIATE`. Nothing later in the file
# is reachable until this works, which is why it comes before the remaining types.
#
#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it
#   statement <tab> <tab> -               a command with no result set, only a tag
#   statement <tab> !SQLSTATE message     PostgreSQL refused it; DETAIL and HINT follow
#
# THINGS REASONING WOULD GET WRONG
#
#   * **One SQLSTATE, two sentences, and the second names both tables.** Writing a child row that
#     points at nothing is `insert or update on table "fxc" violates …` with
#     `Key (p)=(99) is not present in table "fxp".`; removing a parent row something points at is
#     `update or delete on table "fxp" violates … on table "fxc"` with
#     `Key (id)=(2) is still referenced from table "fxc".` An implementation with one message for
#     both looks right on half the cases.
#   * **A NULL points at nothing and that is not a violation.** `MATCH SIMPLE`, the default:
#     `INSERT INTO fxc VALUES (12, NULL, NULL)` succeeds under the constraint that refuses `99`.
#   * **`UPDATE` on the parent is a referential event too**, and it is the one an implementation
#     that only hooks `DELETE` misses: `UPDATE fxp SET id = 3 WHERE id = 2` is the same `23503`,
#     and under `ON UPDATE CASCADE` it **rewrites the children's key** rather than deleting them.
#   * **`pg_get_constraintdef` prints four things not as they were written**: no space before the
#     parent's column list (`REFERENCES fxp(id)`, where the child's side has one); `ON UPDATE`
#     before `ON DELETE` whichever order was written; **nothing at all** for the default, so
#     `ON DELETE NO ACTION` comes back absent; and `DEFERRABLE` kept while `INITIALLY IMMEDIATE`
#     is dropped — so the exact clause `ActiveRecord` writes is not what comes back out.
#   * **`NO ACTION` and `RESTRICT` are different codes for the same immediate behaviour.**
#     `confdeltype` is `a` and `r`, the definition text differs, and both refuse. The difference on
#     a real server is that `NO ACTION` can be deferred to the end of the statement and `RESTRICT`
#     cannot; with every check immediate the two are one behaviour, which is what the rows show.
#   * **A cascade is a chain.** Deleting `fxq` row 2 removes `fxd` row 12 and then `fxg` row 100,
#     which points at `fxd`. Depth-first, or a row is removed while something still points at it.
#   * **The DDL errors are four different codes.** A missing parent is `42P01`; a missing column is
#     `42703` with a sentence of its own — `column "nosuchcol" referenced in foreign key constraint
#     does not exist`, not the plain one; a referenced column with no unique index behind it is
#     `42830`; a name the table already uses is `42710`. And dropping the parent is `2BP01`.
#   * **`REFERENCES t` with no column list means the parent's primary key**, and derives the name
#     `fxe_p_fkey`. That is the form `t.references :parrot, foreign_key: true` writes.
#
# The tables are left behind on the oracle, which is what lets `\gdesc` fill the declared-types
# column in a second session (`captures/README.md`). They are named `fx*` rather than `fk*`
# because `fk*` belongs to `captures/pg19_ddl_cascade_fk_trigger.txt` and a `DROP … CASCADE` on a
# shared name takes that file's constraints with it.
