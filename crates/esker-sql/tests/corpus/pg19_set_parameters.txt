# `SET` / `SHOW` / `RESET` of run-time parameters — as a real PostgreSQL 19beta1 answers them.
#
# Four rows of run 45's failure ranking are one shape, 33 tests between them, and every statement
# below is verbatim from the test that sends it:
#
#   * `SET lc_monetary` — 12 tests, `adapters/postgresql/money_test.rb:15`, `set lc_monetary = 'C'`
#   * `SET idle_in_transaction_session_timeout` — 10 tests, `connection_test.rb:241`,
#     `set idle_in_transaction_session_timeout = '10ms'`
#   * `SET SESSION` — 6 tests, `schema_authorization_test.rb:20`,
#     `SET search_path TO '$user',public`
#   * `SET debug_print_plan` (3) and `SET geqo` (2) — `connection_test.rb`, `SET geqo TO off` with
#     `show geqo` read back
#
# Note the tests write `set` in lower case as often as upper, and read the value back with `SHOW`
# rather than trusting the `SET` — so `SHOW` is half the requirement, not an extra.
#
# Captured in one session with `scratchpad/sesscap.py` and replayed the same way.
#
# **The whole capture runs inside `BEGIN … ROLLBACK`**, error probes in `SAVEPOINT` / `ROLLBACK TO`.
# The final `SHOW lc_monetary` after the rollback proves the session was left as it was found.
#
# **One value here is a property of the oracle container, not of PostgreSQL**: `lc_monetary`
# defaults to `en_US.utf8` on `esker-pg19`. A replay against a differently-configured server will
# differ on that row and on nothing else; what the suite needs is that `SET` changes it and `SHOW`
# reports the change.
#
#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it
#   statement <tab> <tab> -               a command with no result set, only a tag
#   statement <tab> !SQLSTATE message     PostgreSQL refused it; DETAIL and HINT follow
#
# THINGS REASONING WOULD GET WRONG
#
#   * **`SHOW` returns a one-column row of `text`, whatever the parameter's real type is.**
#     `pg_settings.vartype` says `bool`, `integer` and `string` for these three, and `SHOW` still
#     answers `on`, `10ms`, `C` as text. `current_setting()` is `text` too.
#   * **The value comes back normalised, not as it was sent.** `SET search_path TO '$user',public`
#     reads back from `SHOW search_path` as **`"$user", public`** — requoted and with a space after
#     the comma. An implementation that echoes the input fails the tests that compare the read-back.
#   * **`idle_in_transaction_session_timeout` keeps a unit in the value**: `SHOW` gives `10ms`,
#     and `pg_settings.unit` is `ms` separately. Setting it to `0` reads back as `0`, not `0ms`.
#   * **But the unit it keeps is not the one it was given.** A duration is converted to the
#     parameter's base unit and re-printed in the largest unit that divides it exactly, which is
#     three separate surprises: a bare `250` reads back **`250ms`** (the unit is *added*),
#     `'2000ms'` reads back **`2s`** and `'120s'` reads back **`2min`** (the unit is *promoted*),
#     and `'1500us'` reads back **`2ms`** (the unit is *converted away* — `us` is smaller than the
#     base and never comes back). A node that echoed the unit it was given passes the `'10ms'`
#     line, which is a fixed point of all three rules, and fails every other one.
#   * **The conversion rounds half to *even*, and can round to `0`.** `'1500us'` and `'2500us'`
#     are both `2ms`; `'3500us'` is `4ms`. `'500us'` is **`0`** — which is the spelling of *off*,
#     so the shortest timeouts a client can ask for turn the feature off rather than on. That is
#     `rint`, PostgreSQL's own conversion, and rounding ties up instead would diverge on half the
#     inputs.
#   * **A fraction is legal**: `'1.5s'` is `1500ms`. The count is `strtod`'s, not an integer's.
#   * **Three refusals, not one, and two of them share a sentence.** A value it cannot read is
#     `invalid value for parameter "x": "banana"`; a value whose base-unit magnitude will not fit a
#     C `int` is the *same sentence* plus `HINT: Value exceeds integer range.` (`'2147483648'`,
#     `'25d'`); and a value that fits and is out of range names the range and reports itself **in
#     the base unit** — `SET statement_timeout = '-5s'` is `-5000 ms is outside the valid range for
#     parameter "statement_timeout" (0 ms .. 2147483647 ms)`. All three are `22023`. The range is
#     0 .. INT_MAX base units, so `'24d'` is accepted and `'25d'` is not.
#   * **An unknown parameter is `42704` from all three of `SET`, `SHOW` and `current_setting()`** —
#     the same SQLSTATE and the same sentence, `unrecognized configuration parameter "…"`. But
#     **`current_setting('…', true)` returns NULL instead of raising**: the two-argument form is the
#     documented escape hatch and is the one shape that must not error.
#   * **A bad *value* is `22023`, not `42704`**: `invalid value for parameter "TimeZone":
#     "Nowhere/Notreal"` and `invalid value for parameter "idle_in_transaction_session_timeout":
#     "banana"`. Unknown name and unknown value are different classes.
#   * **`SET LOCAL` inside a transaction is undone by `ROLLBACK`**, and so is a plain `SET` issued
#     inside one — the final `SHOW` after this file's `ROLLBACK` is back to the container default.
#     `RESET <name>` and `RESET ALL` both restore it mid-transaction.
#   * **`SET TIME ZONE 'America/New_York'` is read back with `SHOW TimeZone`** — the parameter's
#     canonical name is `TimeZone`, camel-cased, while the statement that sets it says `TIME ZONE`.
#   * **`current_schemas(false)` is `name[]`**, and with `search_path` set to `'$user',public` it
#     answers `{public}` — the `$user` entry contributes nothing when no schema of that name exists.
