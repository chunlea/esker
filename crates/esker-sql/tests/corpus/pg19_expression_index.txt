# An **expression** index — statement 78 of `schema.rb`, and the partial index's two loose ends
#
# `CREATE UNIQUE INDEX "index_books_on_lower_external_id" ON "books" ((lower(external_id)))`. The
# key is a value computed from the row rather than a column of it, so the `UNIQUE` constrains
# `lower(b)` and two rows may hold `Alpha` and `ALPHA` only if nothing else does.
#
#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it
#   statement <tab> <tab> -               a command with no result set, only a tag
#   statement <tab> !SQLSTATE message     PostgreSQL refused it; DETAIL and HINT follow
#
# THINGS REASONING WOULD GET WRONG
#
#   * **The printed form is not the written form, and one pair of parentheses is not the other.**
#     `((lower(b)))` prints `lower(b)` — the outer pair is the column list's and the inner pair is
#     dropped — but `((b IS NULL))` prints `((b IS NULL))`, keeping both. The rule is about the
#     node and not about the text: a bare function call is listed unwrapped and everything else is
#     wrapped once more than `pg_get_expr` prints it. Measured over a call, a comparison, an
#     `IS NULL`, a cast and two constants; `pg_get_expr(indexprs, …)` is the column that shows the
#     difference, `lower(b)` against `(b IS NULL)`.
#   * **`indkey` is `0` for an expression part**, and `ActiveRecord` branches on exactly that
#     (`indkey.include?(0)`) to decide whether to believe its column list. A key over `a` and
#     `lower(b)` is `2 0`. Attribute numbers are one-based, which is what leaves `0` free.
#   * **A bare column in expression position is a column**: `((b))` has `indkey = 3` and no
#     `indexprs` at all, not an expression that happens to be a variable.
#   * **The derived name takes the function's name**, not `expr`: `((upper(b)))` unnamed is
#     `xidx_upper_idx` and `((b IS NULL))` is `xidx_expr_idx`.
#   * **The `23505` DETAIL names the expression**, in the form `pg_get_expr` prints and not the
#     one the key list uses: `Key (lower(b))=(alpha) already exists.`
#   * **A bad column inside an expression is `42703`, the same as one in the key**, and a wrong
#     argument *type* is `42883` naming the argument type — `lower(bigint)` here where a real
#     server says `lower(integer)`, the bare-integer divergence declared in
#     `tests/unknown_literal.rs`. An aggregate is `42803` with a sentence of its own.
#   * **The index relation has a `pg_attribute` row per key part**, and an expression's is named
#     after the function: `xidx_mixed`'s two rows are `a` and **`lower`**.
#
# THE TWO PARTIAL-INDEX LINES AT THE END ARE REGRESSIONS, not new ground. `pg_get_indexdef` prints
# a `WHERE` — statement 77's unit left it out, and `ActiveRecord` recovers the predicate by
# scanning that string — and `indpred` is that text rather than NULL. The last block is the other
# one: an index built over rows that **already exist** must leave out the rows its predicate
# excludes. Rows 2 and 3 share `b = 7` with a NULL `published_on`, so the index holds only row 1
# and the statement succeeds; a backfill that indexed all three would refuse it with `23505`.
#
# The tables are left behind on the oracle, which is what lets `\gdesc` fill the declared-types
# column in a second session (`captures/README.md`).
