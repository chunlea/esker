# `bigint_array` — the table `postgresql_specific_schema.rb` declares, end to end.
#
# It is the statement `ActiveRecord` failed **client-side** on: `TypeError: can't quote Array`,
# because the adapter decides a column is an array by reading `pg_type.typinput == 'array_in'` and
# no type here answered that. So this corpus is the blocker itself rather than a study of arrays:
# the two columns it declares, the array `DEFAULT` it carries, and what a client is told about
# them.
#
# The three answers that are not about storage at all:
#
#   * `format_type` reports `bigint[]` and `numeric[]` — the *element's* name with `[]`, not the
#     internal `_int8` that `pg_type.typname` holds;
#   * `pg_get_expr` renders the default as `'{1.23,3.45}'::numeric[]`, cast and all;
#   * a bad **element** is the element type's own failure — `'{9223372036854775808}'` into an
#     `int8[]` is `22003 value ... is out of range for type bigint`, and `'{1,x}'` into a
#     `numeric[]` is `22P02 invalid input syntax for type numeric`. Neither is an array error.
#
# And `ORDER BY` over an array column, which is what makes the key encoding's order visible from
# SQL: `{}` first, then the two-element arrays, with a NULL array last under `NULLS LAST`.
DROP TABLE IF EXISTS bigint_array		-
CREATE TABLE bigint_array (id int8 PRIMARY KEY, big_int_data_points int8[], decimal_array_default numeric[] DEFAULT '{1.23,3.45}')		-
