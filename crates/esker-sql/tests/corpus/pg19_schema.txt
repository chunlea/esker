# `CREATE SCHEMA` and the named-schema half of `schema_test.rb` — as a real PostgreSQL 19beta1
# answers it.
#
# `test/cases/adapters/postgresql/schema_test.rb` puts **everything** in `test_schema` and
# `test_schema2` and then asks the adapter to tell them apart: two tables called `things`, two
# indexes of one name over *different columns* in each schema, a schema-qualified `CREATE INDEX`,
# `remove_index` with a schema in either the table's name or the index's, and a `search_path` that
# decides which `things` a bare name means. The statements here are the suite's own, out of its
# `setup` and out of `connection_adapters/postgresql/schema_statements.rb`.
#
# Captured in one session with `scratchpad/sesscap.py` and replayed the same way.
#
# **The whole capture runs inside `BEGIN … ROLLBACK`**, error probes in `SAVEPOINT` / `ROLLBACK TO`.
# The `SELECT count(*)` at the end proves it left nothing behind and answers `0`. `\gdesc` runs
# inline, so every statement has its declared types pinned.
#
#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it
#   statement <tab> <tab> -               a command with no result set, only a tag
#   statement <tab> !SQLSTATE message     PostgreSQL refused it; DETAIL and HINT follow
#
# THINGS REASONING WOULD GET WRONG
#
#   * **`CREATE SCHEMA … CREATE TABLE …` is one statement**, not two. The suite's `setup` writes it
#     that way — `CREATE SCHEMA test_schema CREATE TABLE things (…)` — so a node that reads
#     `CREATE SCHEMA` and stops has not read the table.
#   * **A schema is not a prefix on a name; it is a namespace two names can live in.** After the
#     setup there are two tables called `things` and **two indexes called
#     `a_index_things_on_name`**, one per schema, and `pg_class` returns two rows for each. A
#     catalog keyed by name alone cannot hold this.
#   * **`search_path` decides what a bare name means, and it is ordered.** With
#     `SET search_path TO test_schema` a bare `things` is `test_schema`'s and holds row `1`; with
#     `TO test_schema2, test_schema` the same query is row `2`. Neither schema is on the default
#     path, so before any `SET` the bare name is `42P01 relation "things" does not exist` — even
#     though two tables of that name exist.
#   * **`current_schemas(false)` is the path as resolved, not as written.** `SET search_path TO
#     "$user", public` answers `{public}`: `$user` names no schema here, so it is dropped rather
#     than reported. Its type is `name[]` and `current_schema`'s is `name`.
#   * **Three different codes for three ways of naming a schema wrong.** A schema that is already
#     there is `42P06 schema "test_schema" already exists`; one that is not is `3F000 schema
#     "nosuchschema" does not exist` — including from `CREATE TABLE nosuchschema.t`, which fails on
#     the *schema* rather than the table; and a **relation** in a missing schema is the ordinary
#     `42P01 relation "nosuchschema.t" does not exist`, with the schema **inside the quotes**.
#   * **`DROP SCHEMA` without `CASCADE` is `2BP01` and names one dependent**, the way a table with
#     an inheriting child is: `DETAIL: table test_schema.things depends on schema test_schema`,
#     with the `Use DROP ... CASCADE` hint. `IF EXISTS` covers absence and not dependence, and
#     `DROP SCHEMA IF EXISTS nosuchschema CASCADE` is a plain success.
#   * **`ALTER SCHEMA … RENAME TO` moves every relation with it** and is a catalog-only change:
#     `pg_namespace` shows `test_schema3` and the tables under it are the same tables.
#   * `CREATE SCHEMA IF NOT EXISTS` over an existing one is a **success**, not a notice this
#     capture can see — `psql` prints the notice on stderr and the statement's answer is a tag.
