# The scalar functions `CREATE TABLE "defaults"` calls — statement 738 of the specific schema.
#
# They were "accepted" before only by the old `DEFAULT` whitelist, never as functions: `SELECT
# now()` was `0A000`. Captured in one rolled-back session against PostgreSQL 19beta1.
#
# Nothing here prints a clock reading, because a corpus is replayed and an instant is not
# reproducible. What is pinned instead is every property of these values that *is* stable:
#
#   * **`now()` and `CURRENT_TIMESTAMP` are the same instant** — the transaction's, not the
#     statement's — so they compare equal and their difference is exactly `00:00:00`;
#   * `CURRENT_DATE` is that instant's date;
#   * neither is ever NULL.
#
# The rules that decide an implementation:
#
#   * **`concat` skips NULLs rather than propagating them.** `concat('a', NULL, 'b')` is `ab` and
#     `concat(NULL, NULL)` is the **empty string**, not NULL — the opposite of `||`. It is also
#     variadic and not strict, so `concat()` is a `42883` about the *number* of arguments;
#   * a non-text argument is rendered by its own output function: `concat('n=', 42, ' t=', true)`
#     is `n=42 t=t`, and a `numeric` keeps its scale (`2.50` stays `2.50`);
#   * **`convert_to` is strict** — a NULL in either argument is NULL, encoding name included —
#     and an encoding name that is not one is `22023`, not a refusal;
#   * the encoding name is matched the way `pg_char_to_encoding` matches it: case-insensitively
#     and ignoring `-` and `_`, so `UTF8`, `utf8` and `Utf-8` are one name. `UNICODE` is an alias
#     for it.

SELECT concat('a', NULL, 'b')	text	ab
SELECT concat(NULL, NULL)	text	
SELECT concat('a')	text	a
