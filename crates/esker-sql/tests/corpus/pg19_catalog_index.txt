# `pg_index` and `pg_get_indexdef`, as a real PostgreSQL 19beta1 answers them -- phase 13 unit 2.
#
# What `ActiveRecord`'s `indexes()` reads, joined to `pg_class` twice. Three oids in one statement
# -- `t.oid`, `d.indrelid`, `d.indexrelid`, `i.oid` -- which is why every view in this phase takes
# its oid from one place and none computes one.
#
# Captured in one session with `scratchpad/sesscap.py` inside one `BEGIN ... ROLLBACK`, and
# replayed the same way against one node. The corpus builds its own tables.
#
#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it
#   statement <tab> <tab> -               a command with no result set, only a tag
#   statement <tab> !SQLSTATE message     PostgreSQL refused it; DETAIL and HINT follow
#
# THINGS REASONING WOULD GET WRONG
#
#   * **A primary key has a `pg_index` row**, `indisprimary` and `indisunique` both `t`, and its
#     `indexrelid` is *not* its `indrelid`. Here the row key **is** the primary key and there is no
#     separate index to describe -- and the row is still the right answer, for the reason
#     `pg_class` reports the constraint as a relation: a client can name `ia_pkey`.
#   * **`indkey` is an `int2vector` and prints space-separated**, `3 4` for a two-column index and
#     `1 2` for a two-column primary key. `ActiveRecord` reads it as
#     `row[2].split(" ").map(&:to_i)` -- a text operation on the rendered value -- so `text` here
#     carries the same characters and means the same thing.
#   * **`pg_get_indexdef` never raises.** An oid with no index behind it is **NULL**, including the
#     oid of a *table* (`pg_get_indexdef('ia'::regclass)` is NULL, not an error), and so is a NULL
#     argument. A node that raised would break `indexes()` on the first unusual row.
#   * **It is strict in its *second* argument, which is not the same as having none.**
#     `pg_get_indexdef(oid)` is the whole definition and `pg_get_indexdef(oid, NULL, true)` is
#     **NULL**. An implementation that reads "no column" and "a NULL column" into one `Option`
#     prints a definition where a real server says nothing.
#   * **The three-argument form is three different answers.** `(oid, 0, true)` is the whole
#     definition **without** the `public.` qualifier the one-argument form prints; `(oid, n, ...)`
#     for `n >= 1` is the *column name alone*; and past the last column it is the **empty string**,
#     not NULL and not an error. The `pretty` flag changes nothing for a plain column.
#   * **A table with no primary key and no index has no rows here at all** -- `ib` before its index
#     is created, and `count(*)` for a keyless table is 0.
#
# The three shapes below that are `ActiveRecord`'s own -- `indexes()`, `index_name_exists?` and
# `primary_keys()` -- are the acceptance for this unit. `primary_keys()` needs `= ANY` over an
# `int2vector`, which is the array lane's, and is here so the boundary is measured rather than
# assumed.
