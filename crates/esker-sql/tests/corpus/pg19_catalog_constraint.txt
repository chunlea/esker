# `pg_constraint` and `pg_get_constraintdef`, as a real PostgreSQL 19beta1 answers them --
# phase 13 unit 3.
#
# `ActiveRecord` reads this relation for four things and this node has none of them:
# `foreign_keys()` (contype `f`), `check_constraints()` (`c`), `unique_constraints()` (`u`) and
# `exclusion_constraints()` (`x`). No rows is the *correct* answer about this catalog for three of
# the four -- FOREIGN KEY, CHECK and EXCLUDE are all `0A000` in the DDL -- and a gap for the
# fourth, which the divergence list names.
#
# Captured in one session with `scratchpad/sesscap.py` inside one `BEGIN ... ROLLBACK`, and
# replayed the same way against one node. The corpus builds its own tables.
#
#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it
#   statement <tab> <tab> -               a command with no result set, only a tag
#   statement <tab> !SQLSTATE message     PostgreSQL refused it; DETAIL and HINT follow
#
# THINGS REASONING WOULD GET WRONG
#
#   * **PostgreSQL 19 has a `pg_constraint` row for `NOT NULL`**, contype `n`, named
#     `<table>_<column>_not_null`, whose definition is the two words `NOT NULL id`. That row did
#     not exist in older majors, so a catalog written from an older memory is missing it -- and it
#     is why `information_schema.table_constraints` reports a `NOT NULL` as a **CHECK** (unit 4).
#   * **A primary key's columns each get one, and a column that is both gets one row, not two.**
#     `kc (k1 int8, k2 text NOT NULL, ..., PRIMARY KEY (k1, k2))` has three rows: two `n` and one
#     `p`. A key column is NOT NULL whether it says so or not.
#   * **A table with no key and no NOT NULL column has no rows here at all** -- not an empty
#     constraint, no row. `count(*)` for `kb (a int4, b text)` is 0.
#   * **`confupdtype` and `confdeltype` are a single space for a constraint that is not a foreign
#     key**, not the empty string and not NULL -- where `pg_attribute.attidentity` spells "none"
#     as the empty string. Two neighbouring catalogs, two spellings.
#   * **`conindid` is 0 for a `NOT NULL` and the index's oid for a primary key.**
#   * **`pg_get_constraintdef` never raises**: an unknown oid is NULL, as `pg_get_indexdef`'s is.
#   * **A `UNIQUE` constraint and a `CREATE UNIQUE INDEX` are different things on a real server**
#     and the same record here: `kd_u_key` is both a `u` row in `pg_constraint` and a unique index
#     in `pg_index` there, and only the index here. See the divergence list -- closing it is one
#     bool on the catalog record and therefore a question for a human.
