# THINGS REASONING WOULD GET WRONG
#
#   * **`OWNED BY` does not give the column a default.** `pg_attrdef` still shows one row for a
#     `bigserial` table after a second sequence is created `OWNED BY` that same column — the
#     original one. Ownership says the sequence *goes when the column does*, which points the
#     opposite way from a default, and it takes an `ALTER COLUMN … SET DEFAULT nextval(…)` to make
#     the column use it. A node that wired the default here would answer the suite's next
#     statement before it was asked.
#   * **A column can own more than one sequence.** The statement above is issued against a table
#     whose `id` is already a `bigserial`, so `companies_id_seq` and `companies_nonstd_seq` both
#     belong to `companies.id` and `pg_class` holds both.
#   * **`START 101` is the first value, not the one before it** — `nextval` answers `101` and then
#     `102`. A node that stored the start as "the last value handed out" would be one short for
#     every sequence anyone gave a `START` to.
#   * **A name collision is `42P07` against the whole relation namespace**, not just other
#     sequences: `CREATE SEQUENCE` over a table's name is the same error a table over a table's is.
#   * **`OWNED BY` names a column and both halves can be wrong**: a missing table is `42P01` and a
#     missing column is `42703`, which spells the relation it looked in.
