# `floatrange` and `stringrange` — a column of a **user-defined range type**, against PG 19beta1.
#
# **Run 64's row: 46 tests in `adapters/postgresql/range_test.rb`**, which had moved from
# `tstzrange[]` to `a column of the range type floatrange is not supported`. The file's `setup`
# declares *two* user range types in one transaction and adds a column of each, so either one
# missing fails all 46 — `floatrange` (`subtype = float8, subtype_diff = float8mi`) and
# `stringrange` (`subtype = varchar`).
#
# The six values are the file's own `insert_range(id: 101…106)` fixtures plus the two rows that
# are not ranges: 108 is NULL and 109 is `range_test.rb`'s escaped string range, whose bounds are
# `ca"t` and `do\g`.
#
# Things reasoning would get wrong:
#
# * **A continuous subtype does not canonicalise.** `[0.5,0.7]` comes back exactly as written,
#   where `int8range '[10,100]'` comes back `[10,101)`. `pg_range.rngcanonical` is `-` for a
#   `float8` range, as it is for `numrange` — measured, both.
# * **`[0.5,0.5)` is `empty` and `[,]` prints `(,)`**: an absent bound is never inclusive whatever
#   bracket was written beside it.
# * **`-Infinity` is a value, not an unbounded bound.** `[-Infinity,Infinity]` keeps its square
#   brackets and `upper_inf` is `f`, where `[0.5,]` prints `[0.5,)` and `upper_inf` is `t`.
# * **A `varchar` bound is quoted and keeps its whitespace**: `["ca""t","do\g")` round-trips byte
#   for byte, and `'["a b","c d")'` keeps the quotes it needs.
# * **Range order is not text order.** `ORDER BY float_range` is `empty`, `(,)`,
#   `[-Infinity,Infinity]`, `[0.5,0.7)`, `[0.5,0.7]`, `[0.5,)` — sorted by lower bound and then by
#   inclusivity, so `empty` comes **first**. Sorting the canonical text agrees on everything
#   except `empty`, which the text sorts last.
# * **A range type is its own type.** `float_range = '[0.5,0.7]'::numrange` is `42883`, and
#   `min(floatrange)` does not exist any more than `min(tsrange)` does.
# * **`CREATE TYPE … AS RANGE (subtype = point)` is `42704`**, with the *same* message
#   `CREATE INDEX` on a point column gives and a different HINT: a range needs its subtype to have
#   a btree operator class, because that is what orders the bounds.
#
