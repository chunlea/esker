# `smallint` / `int2`, as a real PostgreSQL 19beta1 answers it — tier 1's fourth type
# ([ADR 0033](../../../../docs/adr/0033-tier-1-of-the-type-surface.md)), and `smallserial` with it.
#
# Captured in one session with `scratchpad/sesscap.py` and replayed the same way against one node.
# It builds its own table.
#
#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it
#   statement <tab> <tab> -               a command with no result set, only a tag
#   statement <tab> !SQLSTATE message     PostgreSQL refused it; DETAIL and HINT follow
#
# The shape is `int4`'s exactly, one width down, and that is the point of capturing it rather than
# deriving it: both ends of the range are here and so is every direction past them, so a mapping
# onto `int4` or `int8` answers every `22003` line with a stored row.
#
# **`22003` has two messages**, as it does for `integer`: a *constant* out of range is a bare
# `smallint out of range`, and a *string* out of range is `value "32768" is out of range for type
# smallint`. One is the assignment noticing the constant will not fit, the other is `int2in`
# failing.
#
# `smallserial` is here because it is not a type either: column `s` is a `smallint` that fills
# itself, and `\gdesc` calls it `smallint`.
CREATE TABLE i2 (id int8 PRIMARY KEY, n smallint, m int2, w integer, s smallserial)		-
INSERT INTO i2 (id, n, m, w) VALUES (1, 10, 10, 100)		-
INSERT INTO i2 (id, n, m, w) VALUES (2, -32768, -32768, 200)		-
INSERT INTO i2 (id, n, m, w) VALUES (3, 32767, 32767, 300)		-
SELECT id, n, m, w, s FROM i2 ORDER BY id	bigint,smallint,smallint,integer,smallint	1|10|10|100|1 ; 2|-32768|-32768|200|2 ; 3|32767|32767|300|3
