# `BETWEEN` — run 57's top row, 15 tests over 5 files.
#
# `ActiveRecord`'s range conditions compile to it: `where(id: 1..3)` is
# `"topics"."id" BETWEEN $1 AND $2`, and the failures name six tables' columns at four types.
#
# **The whole feature is a rewrite**, and this file is what says so: `a BETWEEN x AND y` is
# `a >= x AND a <= y`, and every fact below falls out of that rather than needing a rule.
#
# * **Inclusive at both ends and not symmetric.** `id BETWEEN 3 AND 2` matches nothing; only
#   `BETWEEN SYMMETRIC` sorts the bounds.
# * **NULL is three-valued AND, not "NULL anywhere means NULL".** `1 BETWEEN NULL AND 2` is NULL
#   and `3 BETWEEN NULL AND 2` is **false** — because `3 <= 2` is false and false wins over NULL in
#   an `AND`. An implementation that special-cased a NULL bound would answer NULL for both.
# * **A type mismatch names `>=`**, not `BETWEEN`: `title BETWEEN 1 AND 2` is
#   `42883 operator does not exist: character varying >= integer`. The message is the rewrite
#   showing through, which is what says the rewrite is what a real server does too.
# * **`NOT BETWEEN` is `NOT (…)` and inherits the NULL**, so `1 NOT BETWEEN NULL AND 2` is NULL
#   rather than true.
#
# The capture runs inside `BEGIN … ROLLBACK`; the error probe sits in `SAVEPOINT`/`ROLLBACK TO`,
# and the `SELECT count(*)` after the `ROLLBACK` proves it left nothing behind.
#
