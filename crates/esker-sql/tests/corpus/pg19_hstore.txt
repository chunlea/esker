# `hstore` as a **column type and a value** — what `hstore_test.rb` sends, as PostgreSQL 19beta1
# answers it.
#
# Run 47's ranking row 7 is `extension "…" is not available`, **114 tests over 9 files**, and hstore
# is the bulk of it. `captures/pg19_extensions.txt` already pins the *install* mechanics —
# availability, `CREATE`/`DROP EXTENSION`, the error probes — and this file does not repeat them: it
# is the type once it is installed.
#
# **Derived from `esker-rails-harness/captures/pg19_hstore_citext.txt` and re-captured on its own.**
# r1's file measures hstore and citext in one session, and citext is a later unit — replayed here,
# its first refusal would abort the transaction and swallow every hstore statement after it. So the
# hstore statements were taken from r1's list and run as their own `BEGIN … ROLLBACK` session with
# `scratchpad/sesscap.py`; every answer they share is byte-identical to r1's. The citext half stays
# in r1's file for the unit that takes it.
#
# The `SELECT count(*)` lines after the `ROLLBACK` prove it left nothing behind, and both answer 0.
# The `\gdesc` pass runs after that rollback, so every statement naming `hstore` has an **empty**
# declared-types column; the `pg_typeof` lines pin the types instead.
#
#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it
#   statement <tab> <tab> -               a command with no result set, only a tag
#   statement <tab> !SQLSTATE message     PostgreSQL refused it; DETAIL and HINT follow
#
# THINGS REASONING WOULD GET WRONG
#
#   * **An hstore does not print as it was written.** `'a=>b, 1=>2'` comes back
#     `"1"=>"2", "a"=>"b"` — **ordered by key, every key and value quoted, `, ` between pairs** — so
#     the output function is a canonical form and not an echo. A round trip that returned the input
#     would pass `test_parse1` and fail everything after it.
#   * **The order is the key's LENGTH first and its bytes second**, which is the one rule here that
#     plain reasoning gets backwards: `'z=>1, aa=>2'` prints `"z"=>"1", "aa"=>"2"` — `z` before
#     `aa`, where any byte-wise sort puts `aa` first. `'bb=>1, a=>2, ccc=>3, b=>4'` is
#     `"a", "b", "bb", "ccc"`: within one length it *is* byte order, which is why a shorter corpus
#     would have agreed with the wrong rule. Probed for this file rather than found in the suite.
#   * **A repeated key in one literal keeps the FIRST**, and `||` keeps the **right**:
#     `'a=>1, a=>2'` is `"a"=>"1"` while `'a=>1'::hstore || 'a=>2'::hstore` is `"a"=>"2"`. Two
#     opposite rules for the same collision, and both are measured below.
#   * **An unquoted `NULL` value is case-insensitive and is a real NULL** — `a=>null` and
#     `b=>NuLl` are both NULL — while a *quoted* `"NULL"` is the four-character string. Whitespace
#     around a key or a value is trimmed: `'  a  =>  b  '` is `"a"=>"b"`.
#   * **A NULL value is the bare word `NULL`, unquoted, and is a real NULL**: `'key=>NULL'` prints
#     `"key"=>NULL` and `->'key'` `IS NULL` is `t`. A *key* called `NULL` is quoted like any other
#     — `'NULL=>NULL'` is `"NULL"=>NULL` — so the two spellings of the same four letters mean
#     different things on the two sides of `=>`.
#   * **`''::hstore` is an empty hstore, not NULL.** It equals itself, `IS NULL` is false, and it
#     prints as the empty string — which is why `t.hstore "tags", default: ""` needs the empty
#     string and the NULL told apart.
#   * **`=>` inside a value needs no escape**: `'a=>b=>c'` is `"a"=>"b=>c"`, one pair. But a bare
#     `'a'` is **`42601 syntax error in hstore: unexpected end of string`** — a syntax error, not
#     `22P02`, which is the class every other bad literal in this crate uses.
#   * The quoting the suite actually pushes through, from `test_quotes`, `test_backslash`,
#     `test_comma` and `test_parse6/7`: `\"`, `\\`, a comma inside a key, and `}`. Those exact pairs
#     are below, and a parser that handles `a=>b` and not these passes no test in that file.
#   * **`->` is `text`, `akeys` is `text[]`, `?` is `boolean`** — measured, and `->` on a missing
#     key is NULL rather than an error.
#   * **`hstore[]` escapes the whole hstore inside the array**: an element `"AA"=>"BB", "CC"=>"DD"`
#     prints as `"\"AA\"=>\"BB\", \"CC\"=>\"DD\""`. A NULL *value inside* an hstore inside an array
#     is not a NULL element, and `test_change_table_supports_hstore` needs both.
#   * **A default prints with its own cast**: `''::hstore`, and
#     `'"users"=>"read", "articles"=>"write"'::hstore` — the canonical form, quoted and cast, which
#     is what `ActiveRecord`'s `column_defaults` reads.
#   * **The oid is assigned when the extension is installed and is never fixed.** AR's boot
#     type-map query reads it by `typname`; `typcategory` is `U`, `typinput` is `hstore_in`, and
#     `typarray` is not zero. Nothing may hard-code the number.
