# `t.index [:firm_id], name: "company_nulls_not_distinct", nulls_not_distinct: true`. The one
# clause in an index definition that changes which rows are **refused** rather than how they are
# stored or printed.
#
#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it
#   statement <tab> <tab> -               a command with no result set, only a tag
#   statement <tab> !SQLSTATE message     PostgreSQL refused it; DETAIL and HINT follow
#
# THINGS REASONING WOULD GET WRONG
#
#   * **The default is that NULLs do not collide, and this clause is what reverses it.** A
#     `UNIQUE` index normally admits any number of NULLs, because two unknowns are not known to be
#     equal. Rows 2 and 4 below both have `b = NULL` and the second is `23505` — but the same two
#     rows have `a = NULL` under a plain unique index and are both admitted. One table, two
#     indexes, opposite answers about the same pair of NULLs.
#   * **The DETAIL writes the NULL as `null`** — lower case, unquoted, no `NULL` keyword:
#     `Key (b)=(null) already exists.`
#   * **An `UPDATE` into the NULL is checked too**, which is the half an implementation that only
#     hooks `INSERT` misses.
#   * **`NULLS DISTINCT` written out prints nothing.** It is the default, so a real server stores
#     it as `f` and `pg_get_indexdef` gives it back with no clause at all — the same
#     "keep only what differs from the default" rule the `DESC` unit met.
#   * **The clause prints after the key list and before the `WHERE`**:
#     `USING btree (a, b) NULLS NOT DISTINCT WHERE (c IS NOT NULL)`.
#   * **A non-unique index takes it, and prints it**, where it can refuse nothing at all. Accepted
#     and stored rather than rejected as meaningless.
#   * **It is a column of `pg_index`, not part of the key** — `indnullsnotdistinct`, beside
#     `indisunique` rather than inside `indkey`.
#
# The table is left behind on the oracle, which is what lets `\gdesc` fill the declared-types
# column (`captures/README.md`).
