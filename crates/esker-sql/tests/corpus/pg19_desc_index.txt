# THINGS REASONING WOULD GET WRONG
#
#   * **The definition keeps only what differs from the default, and the default depends on the
#     direction.** `(a ASC NULLS FIRST)` comes back `(a NULLS FIRST)` — the `ASC` dropped because
#     it is the default, the `NULLS FIRST` kept because ascending's default is NULLS **LAST**. And
#     `(a DESC NULLS FIRST)` comes back `(a DESC)`, because descending's default *is* FIRST. So
#     the text cannot be round-tripped from what was written: direction and null placement have to
#     be stored and the shortest spelling re-derived. All four combinations are below.
#   * **`indoption` is the bitmask that says so**: `1` is `DESC`, `2` is `NULLS FIRST`. An
#     ascending part is `0`, a plain `DESC` one is **`3`** — descending carries its own default
#     null placement in the same word — and a two-part key is `0 3`.
#   * **The per-column form drops the ordering entirely.** `pg_get_indexdef(ix, 1, true)` over
#     `(a DESC, c DESC)` is `a`, not `a DESC`. `ActiveRecord` gets the ordering by scanning the
#     whole definition, which is the string that has it.
#   * **A constraint has no direction at all.** `ALTER TABLE … ADD CONSTRAINT u UNIQUE (a DESC)` is
#     `42601 syntax error at or near "DESC"` — the grammar has no place for it, unlike
#     `CREATE INDEX`.
#   * **`NULLS` alone is an operator class name.** `CREATE INDEX ON t (a NULLS)` is
#     `42704 operator class "nulls" does not exist for access method "btree"`, not a syntax error:
#     the parser reads the bare word as the opclass slot.
#   * **The order changes nothing a read can see here.** Uniqueness is order-independent, and this
#     node never chooses an index to satisfy an `ORDER BY` — so the rows below are the same rows an
#     ascending index would give, and that is the claim being pinned rather than an omission.
#
# The table is left behind on the oracle, which is what lets `\gdesc` fill the declared-types
# column in a second session (`captures/README.md`).
