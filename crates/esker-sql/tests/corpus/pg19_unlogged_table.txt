# `CREATE UNLOGGED TABLE` — as a real PostgreSQL 19beta1 answers it.
#
# **The largest single row in run 45's failure ranking: 198 tests across 24 files.** And it is one
# setting, not twenty-four needs — `rails/activerecord/test/cases/helper.rb:14-16` does
#
#     if defined?(ActiveRecord::ConnectionAdapters::PostgreSQLAdapter)
#       ActiveRecord::ConnectionAdapters::PostgreSQLAdapter.create_unlogged_tables = true
#     end
#
# unconditionally, for the whole suite. So **every `create_table` any test issues is UNLOGGED**, and
# this is not a niche feature test: it is how ActiveRecord's suite creates every table it makes.
#
# The statements below are what Rails actually emits, obtained by turning the flag on and
# subscribing to `sql.active_record` rather than by reading the adapter source:
#
#     CREATE UNLOGGED TABLE "unlogged_probe" ("id" bigserial primary key, "name" character varying, "n" integer)
#     CREATE UNLOGGED TABLE "unlogged_noid" ("a" integer)
#
# The keyword sits between `CREATE` and `TABLE`; everything after the table name is unchanged from
# the logged form, which is the whole of the grammar difference.
#
# Captured in one session with `scratchpad/sesscap.py` and replayed the same way.
#
# **The whole capture runs inside `BEGIN … ROLLBACK`**, error probes in `SAVEPOINT` / `ROLLBACK TO`.
# The `SELECT count(*)` at the end proves it left nothing behind and answers `0`. The `\gdesc` pass
# runs after the rollback, so statements naming these tables have an **empty** declared-types column;
# the `pg_typeof` line pins `"char"` for `relpersistence`.
#
#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it
#   statement <tab> <tab> -               a command with no result set, only a tag
#   statement <tab> !SQLSTATE message     PostgreSQL refused it; DETAIL and HINT follow
#
# THINGS REASONING WOULD GET WRONG
#
#   * **`relpersistence` is a `"char"` with three values, and `u` is only one of them**: `p`
#     permanent, `u` unlogged, `t` temporary. `CREATE TEMP TABLE` is `t`, not a kind of unlogged.
#   * **The persistence is inherited by everything the table owns.** A `bigserial`'s sequence
#     (`unlogged_probe_id_seq`) and every index including the primary key come out `u` as well. An
#     implementation that stores the flag on the table alone reports the wrong thing for four
#     relations out of five.
#   * **`information_schema.tables` cannot tell them apart.** Both the logged and the unlogged table
#     are `BASE TABLE`. Persistence is visible only in `pg_class.relpersistence`, so a client that
#     reads the information schema has no way to see it — which is why the `relpersistence` column
#     is the whole specification here.
#   * **`ALTER TABLE … SET LOGGED` / `SET UNLOGGED` flips the indexes too**, in the same statement:
#     after `SET LOGGED` the table *and* `unlogged_probe_n_idx` *and* `unlogged_probe_pkey` all read
#     `p`, and `SET UNLOGGED` puts them back.
#   * **A permanent table may not reference an unlogged one**:
#     `42P16 constraints on permanent tables may reference only permanent tables`. The reverse is
#     **allowed** — an unlogged table referencing a logged one is accepted with no error. The rule is
#     one-directional, which is the half a symmetric implementation gets wrong.
#   * **`ALTER TABLE … SET LOGGED` on a TEMP table is `42P16 cannot change logged status of table
#     "temp_probe" because it is temporary`** — same SQLSTATE as the foreign-key rule, different
#     sentence.
#   * **`CREATE UNLOGGED VIEW` is `42601 views cannot be unlogged because they do not have
#     storage`** — a syntax-class error, not `0A000`, and the message explains itself.
#   * **`CREATE UNLOGGED TABLE IF NOT EXISTS` on an existing table is a plain success**, no error and
#     no notice row here.
