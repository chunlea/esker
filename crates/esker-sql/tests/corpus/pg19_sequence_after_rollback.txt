# THINGS REASONING WOULD GET WRONG
#
#   * **A sequence that was rolled back is gone, numbers and all**: the next one — a serial of another table, or a
#     sequence of the very same name — starts at `1`, and its `currval` is not defined until this session draws
#     from it (`55000`). A `ROLLBACK TO` a savepoint taken before it takes it back the same way, whether `CREATE TABLE`
#     or `ALTER TABLE … ADD COLUMN` made it, and so does the implicit transaction of a `DO` block that raised.
#   * **A rollback still gives no number back to a sequence that survives it**: `nextval` is not transactional, so
#     after `ROLLBACK TO` a sequence goes on from `3` and a serial from `2`.
#   * **`START` holds in the transaction that made the sequence**: `101`, then `102`.
#

ROLLBACK		-

ROLLBACK		-
# the third session: an explicit sequence that hands out three numbers and is rolled back
BEGIN		-

SELECT 'r', nextval('s2f_s'), nextval('s2f_s'), nextval('s2f_s')		r|1|2|3
ROLLBACK		-
# the fourth session: the same name again
BEGIN		-

ROLLBACK		-
# the fifth session: a savepoint's rollback does not give numbers back, to a sequence or to a serial
BEGIN		-
