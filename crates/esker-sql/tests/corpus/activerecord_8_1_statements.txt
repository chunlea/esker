# Every statement ActiveRecord 8.1.3.1 sent a real PostgreSQL 19beta1, in the order it sent them.
#
# Captured from the **server's** log (`log_statement = 'all'` plus `docker logs esker-pg19`), not
# from Rails': what is recorded is what PostgreSQL received, and a client library's own logging is
# a second thing that can be wrong. Taken by `capture-ar-boot.sh` in the out-of-repo harness
# (`docs/plans/phase-9-rails.md` §0), which drives `establish_connection`, a migration, ordinary
# CRUD, and a schema dump -- deliberately not a `rails new` app, because an app adds a framework's
# worth of statements that have nothing to do with the adapter.
#
# **This is not a parity corpus.** The other files under `corpus/` record what PostgreSQL *answered*
# and require this node to answer the same. These queries read PostgreSQL's own catalog, whose
# contents this node does not and should not reproduce, so what is pinned here is the **statement
# text**: the specification for what a Rails-compatible node has to be able to parse and run.
#
# `tests/activerecord_surface.rs` replays it and asserts contract C2 over the whole file -- every
# statement either executes or is refused **by name**, never with a syntax error -- and counts how
# many execute. That count is a progress number, and it is expected to be low.
#
# One statement per line, duplicates removed, whitespace collapsed, in first-issued order.
#
