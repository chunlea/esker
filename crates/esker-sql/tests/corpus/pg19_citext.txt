# `citext` as a **column type and a value** — what `citext_test.rb` sends, as PostgreSQL 19beta1
# answers it.
#
# The other half of run 47's ranking row 7 (`extension "…" is not available`, 114 tests over 9
# files); `tests/corpus/pg19_hstore.txt` is the first half and `captures/pg19_extensions.txt` pins
# the install mechanics, which this file does not repeat.
#
# **Derived from `esker-rails-harness/captures/pg19_hstore_citext.txt` and re-captured on its own**,
# for the reason the hstore corpus says: r1's file measures both types in one stateful session, so
# replaying it whole makes one type's gap swallow the other's statements. Every answer they share is
# byte-identical to r1's. Six statements were added here and are marked below — the ones that decide
# how the type has to be *built*, which the suite's own statements do not.
#
# The `SELECT count(*)` lines after the `ROLLBACK` prove it left nothing behind, and both answer 0.
#
# THINGS REASONING WOULD GET WRONG
#
#   * **`citext` is not `text` with a `lower()` around it, and the suite asserts exactly that**:
#     `test_case_insensitiveness` requires `ActiveRecord` to emit **no** `lower(...)`, so `=` itself
#     folds case. `'ABC'::citext = 'abc'` is `t` where the same comparison over `text` is `f`.
#   * **This database cannot tell citext's *ordering* from `text`'s**, and that is worth knowing
#     before writing a test that thinks it can: the container's collation is `en_US.utf8`, under
#     which `'B' < 'a'` is already `f` for plain `text`. So `'B'::citext < 'a'::citext` being `f`
#     proves nothing, and the ordering probe is here to record that it proves nothing. What
#     separates the two types on this oracle is **equality**, and everything that follows from it:
#     `DISTINCT`, `GROUP BY`, and a unique index.
#   * **`GROUP BY` keeps the first row's spelling**: two rows `Cased Text` and `CASED TEXT` are one
#     group printed `Cased Text`, and `count(DISTINCT cival)` is 1. The value that comes *back* is
#     the one that was stored, never a folded one — `SELECT cival WHERE cival = 'cased text'`
#     answers `Cased Text`.
#   * **A unique index over citext folds case, and that is what the suite needs it for**:
#     `validates_uniqueness_of` is enforced by one, and the index cannot even be *built* over two
#     rows differing only in case — `23505 could not create unique index … Key (cival)=(Cased Text)
#     is duplicated`, with the **stored** spelling in the DETAIL. The insert that then collides is
#     the ordinary `23505 duplicate key value violates unique constraint`, quoting the **new**
#     value's spelling.
#   * **`lower`, `upper`, `length` and `||` all answer `text`**, not citext: `pg_typeof('x'::citext
#     || 'y')` is `text`. The type is not preserved through a function or a concatenation, so only
#     a column, a cast and a comparison carry it.
#   * **The folding is not ASCII-only**: `'Ä'::citext = 'ä'::citext` is `t`. A build whose `lower`
#     is ASCII-only answers `f` there and is wrong for every non-English application.
#   * `indexdef` prints the index as `USING btree (cival)` with **no** `lower(...)` in it, which is
#     the other half of what `test_case_insensitiveness` reads.
