# What a real PostgreSQL 19beta1 does with a **derived table** -- `FROM (SELECT …) AS t`, phase 12
# unit 2 (`docs/plans/phase-12-subquery.md`). Captured before a line of the implementation, in ONE
# session inside `BEGIN ... ROLLBACK` with `ON_ERROR_ROLLBACK on`, so the shared oracle is left
# exactly as it was found.
#
#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it
#   statement <tab> <tab> -               a command with no result set, only a tag
#   statement <tab> !SQLSTATE message     PostgreSQL refused it; DETAIL and HINT follow
#
# THE THREE THAT WOULD HAVE BEEN GOT WRONG BY READING RATHER THAN MEASURING:
#
#   1. **the alias is OPTIONAL on 19.** It was mandatory before PostgreSQL 16 and most of the
#      documentation a reader finds still says so. `SELECT * FROM (SELECT id FROM dt_a)` runs, and
#      the relation simply has no name to qualify with.
#   2. **a column alias list may be SHORTER than the target list.** `AS t (a)` over two columns
#      renames the first and leaves the second under its own name -- so `SELECT a, n FROM … AS t(a)`
#      is a legal statement returning both. Only a *longer* list is an error, and it is `42P10`
#      with a sentence that counts both sides. Refusing a short one reads like the obvious symmetry
#      and would refuse a statement a real server runs.
#   3. **a `FROM` item cannot see the ones beside it.** `FROM (SELECT … WHERE id = a.id) AS t, dt_a a`
#      is `42P01 missing FROM-clause entry for table "a"` even though `a` is right there -- that is
#      what `LATERAL` is for, and the error says so by not existing.
#
# And two the capture pins because a plausible implementation gets them backwards: a name the alias
# list replaced is **gone** (`t.id` is `42703` after `AS t (a, b)`), and duplicate output names
# inside the derived table are legal until something references one, which is `42702`.
CREATE TABLE dt_a (id int8 PRIMARY KEY, n text, k int8)		-
INSERT INTO dt_a VALUES (1, 'one', 7), (2, 'two', NULL), (3, NULL, 9)		-
CREATE TABLE dt_b (id int8 PRIMARY KEY, a_id int8, v int8)		-
INSERT INTO dt_b VALUES (10, 1, 100), (11, 1, 200), (12, 3, NULL)		-

# --- THE ALIAS IS OPTIONAL on 19, and then there is no name at all
SELECT * FROM (SELECT id FROM dt_a)	bigint	1 ; 2 ; 3

SELECT * FROM (SELECT id FROM dt_a) WHERE id = 2	bigint	2

# --- the column alias list: shorter is legal, longer is 42P10, and it REPLACES

SELECT id FROM (SELECT id, n FROM dt_a) AS t (a, b) ORDER BY a	!42703 column "id" does not exist
SELECT * FROM (SELECT id, n FROM dt_a) AS t (a) ORDER BY a	bigint,text	1|one ; 2|two ; 3|\N
SELECT n FROM (SELECT id, n FROM dt_a) AS t (a) ORDER BY a	text	one ; two ; \N
SELECT a, n FROM (SELECT id, n FROM dt_a) AS t (a) ORDER BY a	bigint,text	1|one ; 2|two ; 3|\N
