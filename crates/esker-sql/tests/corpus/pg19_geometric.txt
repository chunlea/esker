#
# **Run 71's row: 9 tests in `adapters/postgresql/geometric_test.rb`.** The file declares five of
# the six in one `create_table` and `line` in a table of its own, and inserts each value **twice**,
# in two different spellings, asserting one answer — which is what makes the canonicalisation the
# subject rather than the storage.
#
# Things reasoning would get wrong:
#
# * **A `box` reorders its corners**: upper right first, then lower left, whatever order it was
#   written in. `geometric_test.rb` has a comment on that line.
# * **A `path`'s bracket is data**: `[…]` is open and `(…)` is closed, `isopen`/`isclosed` report
#   which, and a bare list of points is *closed*. A `polygon` is always written closed.
# * **Every one of the six reads more spellings than it writes** — a `circle` takes four.
# * **None of the six is an index key.** `CREATE INDEX` on an `lseg` is
#   `42704 … has no default operator class` and `count(DISTINCT)` over one is
#   `42883 could not identify an equality operator for type lseg` — even though `=` and `<` both
#   answer. Same shape as `point`, one family along.
# * **`{0,0,0}` is not a line**: `22P02 invalid line specification: A and B cannot both be zero`,
#   its own sentence.
# * `poly_in`, not `polygon_in` — the input function is named for the C type, as `money`'s is
#   `cash_in`.
