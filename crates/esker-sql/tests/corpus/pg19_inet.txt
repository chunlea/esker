# `inet`, `cidr` and `macaddr` — against PostgreSQL 19beta1.
#
# **Run 59's tier-3 row: 8 tests in `adapters/postgresql/network_test.rb`**, whose `setup`
# declares all three in one `create_table`, each with a default — so any one missing fails all 8.
#
# Things reasoning would get wrong:
#
# * **`inet` and `cidr` are one representation and two types.** `'192.168.1.1'::inet =
#   '192.168.1.1'::cidr` is `t`, so under ADR 0042 they may share one; what differs is the input
#   rule and the output. An `inet` **hides a full-length prefix** and a `cidr` never does:
#   `'172.16.1.254/32'::inet` prints `172.16.1.254`.
# * **A missing octet is a prefix, not a zero**: `'10/8'` is `10.0.0.0/8` and `'192.168.1'` is
#   `192.168.1.0/24`. The octets that were written set the default prefix, 8 bits each.
# * **A `cidr` refuses bits to the right of its mask** — `22P02 invalid cidr value` with a DETAIL
#   of its own — and **the `inet::cidr` cast zeroes them instead**: `'192.168.1.5/24'::inet::cidr`
#   is `192.168.1.0/24`. The cast is not "print it and read it back".
# * **`::text` is not the output function either**: `'192.168.1.1'::inet::text` is
#   `192.168.1.1/32`, prefix included, where the same value as a field is `192.168.1.1`.
# * **`macaddr` is six bytes, category `U`, and four input spellings** — `Ab:Cd:Ef:01:02:03`,
#   `0123.4567.890a`, `01-23-45-67-89-0a`, `0123456789ab` — all lower-cased on the way out, which
#   is why the suite's "changing the case does not mark it dirty" test passes there.
# * **A zone id is refused**: `'fe80::1%eth0'::inet` is `22P02` on a real server too.
# * `inet = text` is `42883`; `inet = cidr` is `t`.
#
