# `numeric` arithmetic, as a real PostgreSQL 19beta1 answers — the exact half of the operators.
#
# The scale is part of the answer here in a way it is not for a float, and each rule is its own
# rule rather than one rounding policy:
#
#   * **addition and subtraction take the larger scale**: `1.5 + 1.25` is `2.75`;
#   * **multiplication takes the sum of the scales**: `1.50 * 1.50` is `2.2500`, not `2.25`, and
#     `0 * 3.14` is `0.00`. Nothing is stripped — the scale says how many places the value is
#     known to, and multiplying two known values knows more places rather than fewer;
#   * **division aims at sixteen significant digits**, which is `select_div_scale` in `numeric.c`
#     and not a fixed number of places: `10 / 3` gets sixteen fractional digits and `1 / 3` gets
#     twenty, because the first has a digit before the point;
#   * `%` takes the **larger** scale and the **dividend's** sign: `10.5 % 3` is `1.5`,
#     `(-10) % 3` is `-1` and `10 % (-3)` is `1`.
#
# And the non-finite rules, which are not the float ones by assumption but by measurement:
#
#   * **`'NaN' / 0` is `NaN` and `'Infinity' / 0` is `22012`.** A value that absorbs everything
#     absorbs the error too, and one that does not, does not — the same shape as the NULL rule;
#   * `Infinity * 0`, `Infinity - Infinity`, `Infinity / Infinity` and `Infinity % 3` are `NaN`;
#   * `3 % Infinity` is 3 and `0 / Infinity` is 0.
