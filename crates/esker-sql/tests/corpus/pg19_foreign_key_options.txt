# The four foreign-key/column options `migration/foreign_key_test.rb` needs — captured from the
# statements PostgreSQL 19 actually logged while running that file green (88 runs, 0 errors).
#
# **Run 56: the file is 88 runs / 3 failures / 79 errors.** 69 of those errors were the renamed-index
# name leak and closed with `00203bf`; measured at that commit the file is 6 failures / 10 errors,
# and what is left is exactly four things, all in this capture:
#
# * `ALTER TABLE … ALTER COLUMN … SET NOT NULL` / `DROP NOT NULL` — 3 tests. AR's
#   `change_column_null`.
# * `FOREIGN KEY … DEFERRABLE INITIALLY DEFERRED` — 3 tests. Refused by name because every check
#   here is immediate, and accepting it would refuse a transaction PostgreSQL commits.
# * `ON DELETE SET NULL` / `ON UPDATE SET NULL` — 3 tests.
# * `NOT VALID` + `ALTER TABLE … VALIDATE CONSTRAINT` — 1 error, and **5 failures that are a wrong
#   answer rather than a refusal**: `convalidated` is hardcoded true, so a constraint added
#   `NOT VALID` reports itself validated and AR's `validate: false` schema dump is wrong (ADR 0031
#   rule 3 — a wrong answer is a bug, not an exclusion).
#
# Things reasoning would get wrong:
#
# * **`NOT VALID` does not mean "unchecked from now on".** New rows are checked from the moment the
#   constraint exists; what `NOT VALID` skips is the scan of the rows already there. So an insert
#   that violates it fails immediately even while `convalidated` is false.
# * **`VALIDATE CONSTRAINT` on an already-valid constraint is a success, not an error**, and it is
#   also a success on a constraint that was never `NOT VALID`.
# * **`SET NOT NULL` scans**: it fails `23502` if a row already holds NULL, and the message names
#   the *column and relation*, not the constraint.
# * **`ON DELETE SET NULL` writes the NULL into the referencing column**, so it needs the column to
#   be nullable — combining it with `NOT NULL` is accepted at DDL time and fails at delete time.
# * **`condeferred` and `condeferrable` are two different booleans**: `DEFERRABLE INITIALLY
#   IMMEDIATE` is deferrable and not deferred.
#
# The whole capture runs inside `BEGIN … ROLLBACK`; error probes sit in `SAVEPOINT`/`ROLLBACK TO`,
# and the `SELECT count(*)` after the `ROLLBACK` proves it left nothing behind.
