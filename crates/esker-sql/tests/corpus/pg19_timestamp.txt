# `timestamp` without time zone, as a real PostgreSQL 19beta1 answers it — tier 1's third type
# ([ADR 0033](../../../../docs/adr/0033-tier-1-of-the-type-surface.md)), and the third thing rung
# 2's migration names: `t.timestamps` compiles to `timestamp(6)`.
#
# Captured in one session with `scratchpad/sesscap.py` and replayed the same way against one node.
# It builds its own table.
#
#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it
#   statement <tab> <tab> -               a command with no result set, only a tag
#   statement <tab> !SQLSTATE message     PostgreSQL refused it; DETAIL and HINT follow
#
# **`timestamp` AND `timestamp(6)` ARE THE SAME TYPE**, which is why this unit can take the
# precision `ActiveRecord` writes without a typmod to keep it in. Six is PostgreSQL's default *and*
# its maximum, so columns `a` and `b` below hold identical values — `a = b` is true for every row —
# and print identically. What differs is one string: `\gdesc` says `timestamp(6) without time zone`
# for the declared one and `timestamp without time zone` for the bare one. A `timestamp(0)` through
# `timestamp(5)` really does round, and those are refused by name until the typmod unit.
#
# WHAT MAKES IT A TYPE AND NOT AN ALIAS FOR `timestamptz`: the text. It prints with **no zone
# suffix** where a `timestamptz` prints `+00`, and it does no conversion — the value that goes in
# is the value that comes out, whatever the session's `TimeZone` is.
#
# THREE THINGS TO READ CAREFULLY:
#
#   * the input error names **`timestamp`**, not `timestamp without time zone`:
#     `22007 invalid input syntax for type timestamp: "not a date"`. The *comparison* error names
#     the long form. Two messages about one type, and neither is the other's.
#   * a seventh fractional digit **rounds**: `.1234565` is stored as `.123456`.
#   * `infinity` and `-infinity` are values, and they print as those words.
