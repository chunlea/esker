# `real` / `float4`, as a real PostgreSQL 19beta1 answers it — tier 1's fifth type
# ([ADR 0033](../../../../docs/adr/0033-tier-1-of-the-type-surface.md)).
#
# Captured in one session with `scratchpad/sesscap.py` and replayed the same way against one node.
# It builds its own table.
#
#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it
#   statement <tab> <tab> -               a command with no result set, only a tag
#   statement <tab> !SQLSTATE message     PostgreSQL refused it; DETAIL and HINT follow
#
# WHAT MAKES IT A TYPE AND NOT AN ALIAS FOR `double precision`: the **text**, and the range.
#
#   * `float4out` prints the shortest digits that round-trip **as an f32**, so `1.0/3.0` is
#     `0.33333334` where a `float8` says `0.3333333333333333`. Storing a `real` as a `double`
#     would print seventeen digits a real server never wrote.
#   * **underflow is an error, not a zero.** `1e-50` is `22003` here where a `float8` holds it as
#     a denormal. Both ends raise, and the message **quotes the value expanded to plain decimal** —
#     `1e40` comes back as forty-one digits — because the literal is a `numeric` on its way in and
#     that is `numeric`'s own text.
#
# The two rules it shares with `float8` and does not re-derive: `-0.0` is stored as `0` (the
# literal goes through `numeric`, which has no signed zero), and `NaN` sorts **above** every
# number, so `n > 0` returns it and `max` is `NaN`.
