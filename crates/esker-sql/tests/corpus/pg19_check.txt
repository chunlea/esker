# `CHECK` constraints — half of statement 52 of `schema.rb`
#
# The other half is `FOREIGN KEY`, which is a unit of its own because it has to *enforce*:
# recording a constraint that does not constrain would let a schema load and then accept the rows
# it forbids, which ADR 0031 calls a wrong answer rather than a gap. Until it lands, an FK is
# `0A000` naming itself.
#
#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it
#   statement <tab> <tab> -               a command with no result set, only a tag
#
# THE RULE MOST LIKELY TO BE GOT WRONG: **a NULL passes.** A `CHECK` fails only when its predicate
# is *false*, and SQL's three-valued logic makes `NULL > 0` unknown rather than false — so
# `INSERT INTO ck VALUES (4, NULL, 'x')` succeeds under `CHECK (p > 0)`. An implementation that
# evaluated the predicate as a boolean and treated "not true" as a violation would reject it.
#
# AND THE NAME IS DERIVED WHEN NOTHING GIVES ONE: a column `CHECK` becomes
# `<table>_<column>_check` — `q text CHECK (q <> '')` on table `ck` is `ck_q_check` — while a
# table-level one with no name becomes `<table>_check`. A duplicate name is `42710`.
#
# This file builds and drops its own tables, so replaying it twice is the same as replaying it
# once — verified by capturing it twice and diffing. The first attempt was **not** idempotent: it
# dropped `ck` and not `ck2`/`ck3`, so the second run met a table that was already there.
#
