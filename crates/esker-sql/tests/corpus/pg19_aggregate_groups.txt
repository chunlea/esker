# **The four small aggregate groups** — against PostgreSQL 19beta1.
#
# Groups 8, 9, 10 and 11 of r1's wire-108 baseline: `sum`/`avg` over a `real`, `min`/`max` over
# `tsvector` and `tsquery`, `array_agg` over a domain column, and `string_agg`.
#
#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it
#   statement <tab> <tab> -               a command with no result set, only a tag
#   statement <tab> !SQLSTATE message     PostgreSQL refused it; DETAIL and HINT follow
#
# THINGS REASONING WOULD GET WRONG
#
#   * **A `real` sums to a `real` and averages to a `double precision`** — the transition types
#     are `float4` and `float8[]`, so one accumulates narrow and the other widens before dividing.
#   * **`min`/`max` do not exist over `tsvector` or `tsquery`**, and the list of types that *do*
#     have them is a census of `pg_proc` rather than a collection of surprises.
#   * **`string_agg`'s NULL delimiter is an empty separator**, not a NULL answer.
#   * **An aggregate over a domain column answers the domain's own array type**, which this node
#     cannot express — the three rows whose *values* depend on which tables the server has are in
#     the capture and not here.
#
# Measured in `tests/captures/pg19_aggregate_groups.txt`.
