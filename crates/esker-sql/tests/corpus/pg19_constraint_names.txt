# The name a constraint is given, found and refused by, beyond the schema it lives in — debt #92 —
# as a real PostgreSQL 19beta1 answers it.
#
# Captured 2026-09-13 by lane s2-plpgsql with `sesscap.py`, in three sessions, each inside
# `BEGIN … ROLLBACK`, every refusal in its own `SAVEPOINT` / `ROLLBACK TO`, in schemas of their own; each
# session's last line proves it left nothing behind: `esker-coord/s2-d92a.stmts` (a `CHECK`'s derived
# name, the one name space a table's constraints share, a `UNIQUE` or `PRIMARY KEY` whose name a relation
# has), `s2-d92d.stmts` (a derived `FOREIGN KEY`, `UNIQUE` and `PRIMARY KEY` name already taken) and
# `s2-d92b.stmts` (`SET CONSTRAINTS` by search path). The `\gdesc` pass runs on a connection of its own,
# where those schemas do not exist, so a statement naming one of them has an empty declared-types column.
#
#!escaped

#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it

# THINGS REASONING WOULD GET WRONG
#
#   * **A `CHECK` is named for the one column its expression reads, not for where it is written**: the
#     column constraint on `b` that reads `a < b` is `ck_check`, and the table constraint `CHECK (b > 0)`
#     is `ck_b_check`. No column, or more than one, is `<table>_check`.
#   * **A derived name that is taken is numbered, and the numbering is against the whole schema**:
#     `nsq_x_check1`, because another table's constraint holds `nsq_x_check`. The same for a derived
#     foreign key (`t_a_fkey1`, and `k_a_fkey1` beside a `CHECK` called `k_a_fkey`), `UNIQUE`
#     (`t_b_key1`) and primary key (`q_pkey1` beside a table called `q_pkey`). A *given* name that is
#     taken is refused instead.
#   * **A table's constraints share one name space, of every kind**: a name the primary key, a `UNIQUE`,
#     a `NOT NULL` or a foreign key holds is `42710` for a `CHECK`, and the other way round. Two given
#     `CHECK`s of one name in one `CREATE TABLE` are a sentence of their own: `check constraint "dup"
#     already exists`, with no relation in it. Another table may hold the same name.
#   * **A `UNIQUE` or `PRIMARY KEY` meets a relation of its name first and a constraint second**:
#     `42P07` for an index or a table of that name, `42710` for a `CHECK` — its name is its index's. A
#     `CREATE UNIQUE INDEX` with a `CHECK`'s name builds, because an index is not a constraint.
#   * **`SET CONSTRAINTS <name>` finds its constraint the way a relation is found**: a qualified name in
#     its own schema (`3F000` for one that is not there), a bare one in the first schema on the search
#     path that has a constraint of that name, and only there — and every constraint of that name in
#     that schema at once.
#
