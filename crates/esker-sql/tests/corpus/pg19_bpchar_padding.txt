# **A `character(n)`'s trailing blanks: which readers see them and which do not**, measured on
# every shape this node can build.
#
# `docs/plans/debts-v1.1.md` #31. A `bpchar` is stored blank-padded and printed padded — `SELECT c`
# over a `character(4)` holding `x` is `x   ` on both servers — and that is where the agreement
# ends. The row was found in `tests/typmod.rs` behind a mis-parse (#20) and four more readers
# turned up while measuring #28.
#
# ## The rule is not "read as text"
#
# It is three rules, and the discriminators are in this file:
#
#     the `text` coercion trims      '[' || c || ']'   ->  [x]      c::text, c::varchar too
#     ... so a text function trims   upper(c)          ->  X        substr, replace, btrim, strpos
#     a comparison ignores them      c = 'x'           ->  t        and c = 'x   ' is t as well
#     `length` has its own           length(c)         ->  1
#     `octet_length` has its own     octet_length(c)   ->  4        the storage, not the value
#     `concat` takes `any`           concat(c, 'z')    ->  x   z    the output function, so padded
#     `LIKE` has its own             c LIKE 'x'        ->  f        the padded value is matched
#     a cast out of bpchar trims     c::varchar        ->  x        and c::name and c::text
#     ... a cast *into* one does not c::char(6)        ->  x     6 bytes, and c::bpchar keeps 4
#
# So `octet_length`, `concat` and `LIKE` are the three that keep the padding, and they are here for
# exactly that reason: a fix that trimmed everywhere would break them, and a corpus without them
# would not say so. `c LIKE 'x'` being **false** while `c = 'x'` is **true** is the sharpest pair.
#
# ## And a bare read is padded on both
#
# `SELECT c` is `x   ` here and there, and `min(c)`/`max(c)` are too. The padding is real storage;
# what differs is who is allowed to see it.
#
# Captured against esker-pg19 (PostgreSQL 19beta1) with
# `sesscap.py src/pg19_bpchar_padding.txt.in`, inside one `BEGIN ... ROLLBACK`. The types field is
# empty throughout: this file is about values, and `sesscap.py` describes nothing for a statement
# over a table the capture created (its `\gdesc` pass runs after the rollback -- r1's, and named
# in `NOTE-for-r1-corpus-escape-contract.md`).
