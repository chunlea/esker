# **`varbit`, the one-word spelling of `bit varying`** — against PostgreSQL 19beta1.
#
# Group 6 of r1's wire-108 baseline. Six probes, one cause: `sqlparser` files `varbit` and
# `bit varying` as two `DataType` variants and only the second was read, so the type this node has
# had since the bit-string unit was unreachable through the spelling a person writes.
#
#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it
#   statement <tab> <tab> -               a command with no result set, only a tag
#   statement <tab> !SQLSTATE message     PostgreSQL refused it; DETAIL and HINT follow
#
# THINGS REASONING WOULD GET WRONG
#
#   * **Both spellings print as `bit varying`.** `varbit` survives only as `pg_type.typname`.
#   * **A cast truncates where an assignment refuses**: `'10101'::varbit(3)` is `101`, and the
#     same value into a `varbit(3)` column is `22001`.
#   * **`min`/`max` do not exist over a bit string** — `42883` — and this node agrees.
#   * **The input function reads a `b` or `x` prefix**, which is not the `B'…'`/`X'…'` literal
#     syntax: `'xff'::varbit` is `11111111`, and `'xyz'::varbit` blames the *second* character.
#   * **A bit string converts with `int4` and `int8` only, and only `bit` does.** Eight rows of
#     `pg_cast`, measured as a census; everything else is `42846`.
#
# Measured in `tests/captures/pg19_varbit.txt`.
