# `relation "…" does not exist` — how PostgreSQL resolves a name, and the two catalog relations
# behind run 51's row.
#
# **Run 51 ranking: `relation "…" does not exist` (unqualified), 47 tests over 16 files.** Unlike the
# rows beside it this is not one gap. The names, from `triage/failures-940aa5a.txt`:
#
#     topics (17)  pg_type (8)  companies (5)  comments (5)  people (4)  p_rockets_s (4)
#     citations (1)  pg_stat_activity (1)  legacy_primary_keys (1)
#
#   * `pg_stat_activity` — `migration_test.rb:1108-1114` asks it whether a connection that held an
#     advisory lock is gone. This node does not have the view at all; the query is below verbatim.
#   * `pg_type` — `connection_adapters/schema_cache_test.rb`, which never names it: this is AR's own
#     boot type-map query being re-issued on a reconnect. The node serves that query in `boot36`
#     (36/36) and in a second database, both checked, so the failure is state-dependent and **is not
#     pinned to a statement yet** — said plainly rather than guessed at.
#   * `topics`, `companies`, `comments`, `people`, `citations`, `p_rockets_s`,
#     `legacy_primary_keys` — suite tables that exist. Not pinned either. One attempt to pin them by
#     replaying a file's traced statements produced a false positive and is recorded as such in
#     `results/run-51.md`: the trace contained the schema load's own `DROP TABLE IF EXISTS "topics"`,
#     and replaying the set in sorted order ran the DROP before the SELECTs.
#
# So this file pins the half an oracle can settle: **what PostgreSQL does when a name is looked up**,
# so an implementation has something to be measured against and the message shapes are right.
#
# Things reasoning would get wrong:
#
# * **`pg_stat_activity` is cluster-wide, not per-database**, and its `datname` column is how the
#   test filters to its own — a per-database view would answer that query with the wrong rows.
# * **`to_regclass` returns NULL where a bare reference raises**, which is the supported way to ask
#   "is this there" without an error, and is not the same as `EXISTS (SELECT … pg_class)`.
# * **An unquoted name is folded to lower case and a quoted one is not**, so `TOPICS`, `topics` and
#   `"Topics"` are two names, not three — and the error text quotes what was *looked up*, folded.
# * **A temp schema's NAME carries the session's backend id** (`pg_temp_22`), so it is session state
#   and never belongs in a corpus. The row below asks `nspname LIKE 'pg_temp%'` instead; the first
#   cut of this file selected the name itself and the replay caught it — which is what the
#   byte-identical rule is there for.
# * **A temp table shadows a permanent one of the same name** for the session that made it, because
#   `pg_temp` comes first in the search path; the permanent one is still there and reachable by
#   qualifying it.
# * **The noun in the message is not always `relation`.** A reference in a query says
#   `relation "x" does not exist`; **`DROP TABLE` says `table "x" does not exist`** — same `42P01`,
#   different word, chosen by the statement rather than by the object. This file was written
#   asserting the opposite and the oracle corrected it. A qualified name is quoted **whole**:
#   `relation "public.nosuchtable" does not exist`, not `"public"."nosuchtable"`.
#
# The whole capture runs inside `BEGIN … ROLLBACK`; error probes sit in `SAVEPOINT`/`ROLLBACK TO`,
# and the `SELECT count(*)` after the `ROLLBACK` proves it left nothing behind.
#
