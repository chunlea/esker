# **`polygon` containment and overlap** — PostgreSQL 19beta1, 2026-09-10.
#
# The polygon half of the (b) direction. `value::geometric` parses and formats and has no
# predicates at all, so this is the specification for writing them.
#
# ## THINGS REASONING WOULD GET WRONG
#
#   * **It checks edges, not vertices.** In the concave outer below, both vertices of an inner
#     edge are inside and the midpoint of that edge is outside, and the containment is `f`. "All
#     points of B are inside A" — which is what the operator reads like — answers `t` there.
#   * **Every geometric comparison is fuzzy, epsilon `1e-6`**, and it is the same constant
#     `point_ne` uses (`pg19_point_ne.txt`): a point `1e-6` *outside* an edge is contained, and one
#     `1e-5` outside is not. A polygon whose edge lies `1e-7` outside is contained. An exact
#     predicate written against the reals is wrong on every cell inside that band.
#   * **The boundary is inside**: a vertex, an edge midpoint, a polygon sharing a vertex, one whose
#     edge is collinear with an outer edge, and a polygon identical to the outer are all contained.
#   * **`&&` includes touching**: two squares sharing only an edge overlap, and so do two sharing
#     only a vertex. It is not "share interior area".
#   * A one-vertex polygon is legal and is contained when that point is.
#
