# **Which types an array shape accepts** — four shapes, the whole probe list.
#
# PostgreSQL 19beta1, 2026-09-10, `127.0.0.1:55432`, one `BEGIN … ROLLBACK` with a
# `SAVEPOINT`/`ROLLBACK TO` per probe and `statement_timeout` set. Wire v3 family **F5**.
#
# Each of the 100 distinct type spellings the wire v3 probe list carries, asked four ways with the
# value bound rather than spliced:
#
#     pg_typeof(ARRAY[x])                                     ctor
#     pg_typeof(array_agg(x))                                 agg
#     pg_typeof((ARRAY[x])[1])                                sub
#     pg_typeof((SELECT u FROM unnest(ARRAY[x]) u LIMIT 1))    unnest
#
# ## The finding: `void` is the only refusal, and all four raise the same one
#
#     42704 could not find array type for data type void
#
# No `DETAIL`, no `HINT`. Everything else answers — `json`, `xml`, `point`, `lseg`, `box` and the
# nine array types `GREATEST` refuses for want of a comparison function all build arrays, because
# an array constructor asks nothing of its element but its type. That is the whole difference
# between this family and F1a.
#
# **So the node's predicate is the type `void`, and must not be "this node has no array for it".**
# `ArrayValue::array_of` answers `None` for `lquery`, `int2vector` and `oidvector` too, and 19beta1
# builds `lquery[]`, `int2vector[]` and `oidvector[]`. Refusing those would turn a wrong *type*
# into a refused *statement* — the worse direction (ADR 0031) — so they stay answering `text[]`
# and are pinned in `tests/array_of_void.rs` against **F6**, which owns them.
#
# ## Two things the sweep found that are NOT this family
#
# **`array_agg` over an array is the array, not an array of it**: `array_agg(int2vector)` is
# `int2vector` and `array_agg(bigint[])` is `bigint[]`, because `array_agg(anyarray)` accumulates
# into one more dimension of the same type. `ARRAY[bigint[]]` is `bigint[]` for the same reason —
# PostgreSQL has no nested array types, only more dimensions.
#
# **`unnest` in the FROM clause loses the element type on this node**, and it is a separate
# mechanism: measured, `SELECT unnest(ARRAY['2020-01-01'::date])` describes as `date` (correct)
# while `SELECT u FROM unnest(ARRAY['2020-01-01'::date]) u` describes as **`text`** — 50 of the
# 100 spellings, and `regclass` is worse: `XX000 internal error: regclass() reached the row
# evaluator unresolved`. Family **F10** in `esker-coord/b4-wire-v3-families.md`; nothing here
# touches it.
#
