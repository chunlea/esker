# `CREATE VIEW` / `DROP VIEW` — `view_test.rb`, including the name it deliberately chose.
#
# **Run 53 ranking: `CREATE VIEW is not supported`, 21 tests in one file.** Another new row from
# tests getting further than before. The file's `setup` is one statement and its `teardown` is one
# (`view_test.rb:88-93`):
#
#     CREATE VIEW "ebooks'" AS SELECT id, name, cover, status FROM books WHERE format = 'ebook'
#     DROP VIEW "ebooks'"
#
# Things reasoning would get wrong:
#
# * **The view is named `ebooks'` — with an apostrophe in it.** That is not a typo in this file, it
#   is the suite's own choice, and it is the whole point: a double-quoted identifier containing a
#   single quote has to survive `quote_table_name`, the catalog, `pg_get_viewdef` and the schema
#   dumper. An implementation that quotes identifiers by wrapping them in single quotes, or that
#   escapes the two kinds of quote with one rule, fails this file at `setup` and never reaches a test.
# * **A view is a data source and not a table**, the same one-letter distinction as a foreign table:
#   AR maps `VIEW` to `relkind IN ('v','m')` and `BASE TABLE` to `('r','p')`
#   (`postgresql/schema_statements.rb:1171-1176`), and `test_table_exists` asserts `table_exists?` is
#   **false** for this name while `data_source_exists?` is **true**.
# * **A view has no primary key**, and `test_does_not_assume_id_column_as_primary_key` asserts AR
#   finds none even though the view selects `id`. There is no `pg_constraint` row to find — the rows
#   below show the empty answer that has to come back rather than an error.
# * **A simple view is auto-updatable and a `DISTINCT` one is not.** `INSERT`/`UPDATE`/`DELETE`
#   through the first work with no rule or trigger; through the second they raise `55000`.
#   `information_schema.views.is_updatable` is where that is published.
# * **`CREATE OR REPLACE VIEW` may add columns at the end and may not rename or remove one**, which
#   is a different rule from `CREATE TABLE`'s and has its own message.
# * **A materialized view is `relkind = 'm'`, holds rows, and needs `REFRESH`** — the same helper in
#   `view_test.rb:218-222` drives it with `CREATE MATERIALIZED VIEW` / `DROP MATERIALIZED VIEW`.
#
# The whole capture runs inside `BEGIN … ROLLBACK`; error probes sit in `SAVEPOINT`/`ROLLBACK TO`,
# and the `SELECT count(*)` lines after the `ROLLBACK` prove it left nothing behind.
#
# Rows start with a literal `'r'` because `sesscap.py` drops output rows that begin with a space.
