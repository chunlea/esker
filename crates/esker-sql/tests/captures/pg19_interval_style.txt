# **`IntervalStyle`**, all four, over forty-one values — PostgreSQL 19beta1, 2026-09-05.
#
# WHY THIS WAS CAPTURED
#
# Run 100 opened `interval_test.rb`'s bodies for the first time and two of them failed with
# `NoMethodError: undefined method 'iso8601' for nil` — a value that is **gone**, with no error
# anywhere. `ActiveRecord`'s adapter sends `SET intervalstyle = iso_8601` at connect
# (`postgresql_adapter.rb:1001`) and its `OID::Interval#cast_value` does:
#
#     begin   ::ActiveSupport::Duration.parse(value)
#     rescue  ::ActiveSupport::Duration::ISO8601Parser::ParsingError
#             nil
#     end
#
# So a server that answers `6 years 5 mons 4 days 03:02:01` to a client that asked for
# `P6Y5M4DT3H2M1S` hands back nothing and says nothing. This node stored the setting and ignored
# it.
#
# WHAT REASONING WOULD HAVE GOT WRONG — the sign rules, and no two styles agree
#
#   * `postgres` puts a **`+` on a field that follows a negative one**: `-1 mon 1 day` is
#     `-1 mons +1 day`, and `-1 day 1 second` is `-1 days +00:00:01`. This node was printing
#     `-1 mons 1 day`, which is a defect older than the setting and was found by writing the table
#     below rather than by any test.
#   * `iso_8601` never writes `+`, and signs each field on its own: `P-1M1D`, `PT-4H-5M-6S`.
#   * `postgres_verbose` lets the **first non-zero field** decide, writes every later field
#     relative to it, and appends ` ago`: `-1 mon 1 day` is `@ 1 mon -1 days ago`.
#   * `sql_standard` writes **all three parts, each signed**, whenever the parts disagree in sign
#     or both halves are present — including parts that are entirely zero: `1 day -1 hour` is
#     `+0-0 +1 -1:00:00`.
#   * The plural rules differ **within** a style: verbose writes `-1 days` (signed value) and
#     `-1 sec` (absolute value) in the same sentence.
#   * `sql_standard` does **not** zero-pad the hour: `1:00:00` where `postgres` writes `01:00:00`.
#   * Months carry into years on the way out as well as in: `13 months` is `P1Y1M`, `-14 months`
#     is `P-1Y-2M`, and `1 year -1 month` is `11 mons` — normalised at input, so the styles never
#     see the year.
#

# THE SETTING ALSO CHANGES HOW A VALUE IS **READ**, which is the trap in this capture
#
# Under `sql_standard` a leading negative applies to every field that follows. In one session, one
# `SET` apart:
#
#   SET intervalstyle='postgres';      extract(day from '-1 month 1 day'::interval)  ->   1
#   SET intervalstyle='sql_standard';  extract(day from '-1 month 1 day'::interval)  ->  -1
#
# The first version of the table above parsed each string under the style it then rendered in, so
# five rows measured the input rule and the output rule at once and disagreed with a hand-taken
# probe of the same value. Every row above is parsed under `postgres` and only then rendered.
#
# A bare number with no unit is a count of **seconds** — `'5'` is `00:00:05`, and so is the
# trailing `3` in `'5 days 3'` and `'1-2 3'`. Three neighbouring spellings are `22007` there:
# `'3 5 days'` (the number is not last), `'1:00 5'` (the time was already given) and `'3 ago'`.
# `'3e2'` is `22007` too, where a `f64` parse would take it.
#
# NOTHING PERSISTED: the values live in a `TEMP` table inside one `BEGIN … ROLLBACK`, and the
# session's `intervalstyle` is set with `SET LOCAL` so the connection leaves as it arrived.
#
# WHAT THIS NODE DOES WITH IT, and the one thing it does not
#
# The style is applied where a row **leaves for a client** — the `SELECT` funnel and `RETURNING` —
# so a column, an array's elements, an expression's result and an aggregate all follow it. It is
# not applied inside expression evaluation, so `('1 year'::interval)::text` still answers
# `1 year` where a real server answers `P1Y`. That is one declared divergence with a test that
# asserts it on purpose (`tests/interval_style.rs`), and closing it means the session reaching
# `cursor::Env`. Measured under `iso_8601`, all seven of these are `P1Y` there:
#
#   ('1 year'::interval)::text | cast(... AS text) | ... || '' | format('%s', ...)
#   ('1 year'::interval)::varchar | array_to_string(ARRAY[...], ',') | jsonb_build_object('a', ...)
