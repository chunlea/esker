# **`text[]` to `hstore`** — PostgreSQL 19beta1, 2026-09-11, one `BEGIN … ROLLBACK` with
# `CREATE EXTENSION hstore` inside it and **a `SAVEPOINT` per probe**.
#
# The cast matrix's one open row (`pg19_cast_matrix.txt`): this node answered
# `42846 cannot cast type text[] to hstore` where 19beta1 answers `2202E`. The matrix's probe is
# the one-element `{x}`, so the refusal there is about the **array** — which is what says a real
# server attempted the conversion rather than refusing the pair. What was needed was the
# constructor, not a sqlstate.
#
# **stdout and stderr interleave** below; each `ERROR` quotes its own statement.
#
# ## The conversion
#
#     '{a,1}'::text[]::hstore              "a"=>"1"
#     '{a,1,b,2}'::text[]::hstore          "a"=>"1", "b"=>"2"
#     '{}'::text[]::hstore                 the empty hstore
#     '{a,NULL}'::text[]::hstore           "a"=>NULL          a NULL *value* is a value
#     '{a,1,a,2}'::text[]::hstore          "a"=>"1"           the **first** of a repeat wins
#     '{bb,2,a,1,ccc,3}'::text[]::hstore   "a"=>"1", "bb"=>"2", "ccc"=>"3"
#     pg_typeof('{a,1}'::text[]::hstore)   hstore
#
# The order is hstore's canonical one — **length first, then bytes** — and not the order written.
# The duplicate rule is the one a `BTreeMap` gets backwards by default: the first value stays.
#
# ## The two refusals, and they are about different things
#
#     '{x}'::text[]::hstore        2202E array must have even number of elements
#     '{NULL,1}'::text[]::hstore   22004 null value not allowed for hstore key
#     '{NULL,NULL}'::text[]::hstore  22004, the same — it is the key that cannot be NULL
#
