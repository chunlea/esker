# **Which types `min`/`max` aggregate, and which `GREATEST`/`LEAST` compare** — and they are two
# different domains.
#
# PostgreSQL 19beta1, 2026-09-10, one `BEGIN … ROLLBACK`, every probe inside its own
# `SAVEPOINT`/`ROLLBACK TO`, each asked as `pg_typeof(min(x))` over `SELECT <value> AS x`.
# `debts-v1.1.md` #19's neighbours in the wire v3 census: families F1a, F1b and F2 of
# `esker-coord/b4-wire-v3-families.md`.
#
# **Provenance**: `ltree` was already installed on this oracle and `hstore` was created inside the
# rolled-back transaction; after the `ROLLBACK` the extension list is `ltree, pg_trgm, pgcrypto,
# plpgsql, uuid-ossp` — one of the two, and it is the pre-existing one. Nothing was left behind.
#
# ## The finding: `min`/`max` and `GREATEST`/`LEAST` do not have the same type domain
#
#   min(point[])        point[]          GREATEST(point[])   42883 no comparison function
#   min(hstore)         42883 no min     GREATEST(hstore)    hstore
#
# **`min`/`max` refuse iff PostgreSQL has no aggregate for the type**, which is a list in
# `pg_proc`; **`GREATEST`/`LEAST` refuse iff the type has no comparison function**, which is a
# property of its `btree` opclass — and an array has one exactly when its **element** does. So a
# node with one predicate for both is wrong in both directions at once, and a fix that shared a
# list between them would close one family and open another.
#
# **And `min(regclass)` is an `oid`**, not a `regclass`: the aggregate PostgreSQL picks is
# `min(oid)` and the argument is coerced to reach it. `GREATEST(regclass)` keeps `regclass`.
#
# **Both refusals are `42883`, and they come from different places** — measured with
# `\set VERBOSITY verbose`, which prints the source location:
#
#   min(json)          42883 function min(json) does not exist
#                            LOCATION: ParseFuncOrColumn, parse_func.c:643      <- the PARSER
#   GREATEST(json,json) 42883 could not identify a comparison function for type json
#                            LOCATION: ExecInitExprRec, execExpr.c:2274         <- the EXECUTOR
#
# One is a function lookup that fails because no such aggregate exists; the other is an opclass
# lookup that fails when the expression is initialised. Same sqlstate, different sentence,
# different mechanism — which is the structural confirmation of the finding above.
#
