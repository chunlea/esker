# **The comparison family over four types that have no equality** — PostgreSQL 19beta1,
# 2026-09-09. `ON_ERROR_ROLLBACK on`, one `BEGIN … ROLLBACK`.
#
# r1's param census found four rows where this node **answers what PostgreSQL refuses** — `json`,
# `xml`, `point` and `polygon` under `=` — which ADR 0031 ranks as the worse direction. Four rows
# is not the mechanism: these types have neither equality nor ordering, and *every* shape that
# needs one is affected. Twenty shapes by five types, `jsonb` carried as the contrast because it
# has almost everything the other four lack.
#
# ## THINGS REASONING WOULD GET WRONG
#
#   * **`point` has `<>` and no `=`.** Measured twice, and `pg_operator` names the function:
#     `point_ne` exists, `point_eq` does not. Any node that derives "no equality means no
#     inequality" is wrong on exactly this cell, and it is the cell a reasonable implementation
#     would get wrong.
#   * **Three message families, two SQLSTATEs.** An operator that does not exist is
#     `42883 operator does not exist: T = T`; a shape that needs equality without naming an
#     operator — `DISTINCT`, `GROUP BY`, `UNION`, `IN`, `IS DISTINCT FROM` — is
#     `42883 could not identify an equality operator for type T`, and `ORDER BY` says *ordering*
#     rather than *equality*; and an index, `PRIMARY KEY` or `UNIQUE` is
#     `42704 data type T has no default operator class for access method "btree"`. One shared
#     message would be wrong about two thirds of the table.
#   * **The column is legal; only the constraint is not.** `CREATE TABLE (c json)` succeeds and
#     `CREATE TABLE (c json PRIMARY KEY)` does not — so this is not a type this node may refuse to
#     store, only one it may not order.
#   * **Both operand provenances, because the node gets them wrong differently.** With the
#     operand written as a literal it *refuses* — with the wrong code, `0A000` where a real server
#     says `42883`. With the operand taken from a column it *answers*, which is the worse
#     direction and the one r1's census saw. Fifty of the rows below are the column half, added
#     before the fix rather than after: the array unit this week pinned one provenance and shipped
#     half a fix, and this is that lesson applied in advance.
#   * **What they *do* have is not nothing.** `point` and `polygon` answer `~=` (same as), and
#     `polygon` answers `@>`, `<@` and `&&`. `jsonb` answers `@>` and `<@` but neither `~=` nor
#     `&&`. A node that refuses the whole family for these types trades one wrong direction for
#     the other.
#
# ## The measurements
