# `ARRAY( SELECT … )` — the array **subquery** constructor — as a real PostgreSQL 19beta1 answers it.
#
# **This is boot statement 32, the last of `ActiveRecord`'s 36, and it is NOT `ARRAY[…]`.**
#
# This lane called statement 32 "the `ARRAY[...]` constructor" in runs 33, 36, 37 and 38. That was
# wrong, and `540c555` is what exposed it: `8c2a2be` landed the bracket constructor —
# `SELECT ARRAY[1,2,3]` answers `{1,2,3}` on that node — and **boot stayed at 35/36**, because
# statement 32 asks for
#
#     ARRAY( SELECT pg_get_indexdef(d.indexrelid, k + 1, true)
#            FROM generate_subscripts(d.indkey, 1) AS k ORDER BY k )
#
# which is a different grammar production that still refuses. `pg19_array.txt` covers `ARRAY[…]`
# thoroughly and has no row for this form; nothing else in the corpus did either — the only mention
# anywhere was a prose line in `pg19_subquery_activerecord.txt`'s header. Hence this file.
#
# The last statement before the table probes is statement 32 **verbatim**, run against a table and
# two indexes built here, so the whole row `ActiveRecord` expects is pinned and not just the
# fragment.
#
# Captured in one session with `scratchpad/sesscap.py` and replayed the same way.
#
# **The whole capture runs inside `BEGIN … ROLLBACK`**, error probes in `SAVEPOINT` / `ROLLBACK TO`.
# The `SELECT count(*)` at the end proves it left nothing behind and answers `0`. The `\gdesc` pass
# runs after the rollback, so statements naming `"Quoted"` have an **empty** declared-types column;
# every expression that stands alone keeps its types, and they are the specification here.
#
#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it
#   statement <tab> <tab> -               a command with no result set, only a tag
#   statement <tab> !SQLSTATE message     PostgreSQL refused it; DETAIL and HINT follow
#
# THINGS REASONING WOULD GET WRONG
#
#   * **`ARRAY(SELECT …)` over zero rows is `{}`. `array_agg` over zero rows is NULL.** One row in
#     this file asserts both at once: `array_agg(x) IS NULL` is **`t`** and
#     `ARRAY(SELECT x …) IS NULL` is **`f`** over the same empty input. This is not a detail — it is
#     *why* `ActiveRecord` writes statement 32 this way, and an implementation that rewrites
#     `ARRAY(SELECT …)` into `array_agg` returns NULL where Rails expects an empty array.
#   * **`array_length('{}', 1)` is NULL, not 0** — so the empty array is not NULL but reports a NULL
#     length. Two different notions of empty, both observable in one row.
#   * **`ARRAY(SELECT NULL::int4)` is `{NULL}`, a one-element array** — not `{}` and not NULL.
#     Three distinguishable results (`{}`, `{NULL}`, NULL) that a naive implementation collapses.
#   * **`ORDER BY` inside the subquery determines the element order** and is part of the
#     specification: statement 32's `ORDER BY k` is what makes the column list come out in index
#     order. `ARRAY(SELECT x … ORDER BY x DESC)` is `{3,2,1}`. `LIMIT` is honoured too.
#   * **A two-column subquery is `42601 subquery must return only one column`** — and
#     `ARRAY(SELECT)` with **no** select list gives the *same* error, not a syntax error.
#   * **`ARRAY(VALUES (1),(2))` is accepted** — the argument is any subquery, not only `SELECT`.
#   * **Nesting produces a 2-D array and `pg_typeof` still says `integer[]`.**
#     `ARRAY(SELECT ARRAY(SELECT 1))` is `{{1}}` of type `integer[]`; PostgreSQL does not encode
#     dimensionality in the type name.
#   * **The element type is inferred from the subquery's one column**, and a cast applies to the
#     array as a whole: `ARRAY(SELECT 1)::int8[]` is `{1}` of `bigint[]`.
#   * **It correlates.** `ARRAY(SELECT q2.id FROM "Quoted" q2 WHERE q2.id <= q1.id ORDER BY q2.id)`
#     answers `{1}` then `{1,2}` down the outer rows — statement 32 uses exactly this, referencing
#     `d.indexrelid` and `d.indkey` from the outer join.
#   * **Statement 32's whole row is pinned here**, and its declared types are
#     `name, boolean, int2vector, text, text, boolean, text[]` — note `indkey` is an
#     **`int2vector`** printed `2 3`, and the `columns` column is `text[]` holding `{a,b}`.
#     `obj_description` on an index with no comment is NULL in the same result set as one that has
#     a comment.
