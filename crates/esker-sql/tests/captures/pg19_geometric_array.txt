#

# Every element quotes itself inside the array literal, because each of the five prints characters
# the array grammar reserves.
#
# ## Two refusals that are the point of the family
#
#     min(c::circle)                    42883 function min(circle) does not exist
#     '{…}'::circle[] = '{…}'::circle[] 42883 could not identify an equality operator for type circle
#
# **`'<(0,0),1>'::circle = '<(0,0),1>'::circle` is `t`**, and the array comparison beside it is not:
# array equality needs the element type's *btree* equality and a `circle`'s `=` compares areas
# without one. The scalar `=` answering and the array `=` refusing is exactly the shape
# `ColumnType::Lseg`'s doc comment already records for `CREATE INDEX` and `count(DISTINCT)`.
#
# ## And the rule holds for every element type without a btree equality
#
#     min(point) / min(box) / min(lseg) / min(path) / max(polygon) / min(circle) / max(line)
#                                       42883 function min(<type>) does not exist   — all seven
#     '{…}'::point[]  = '{…}'::point[]  42883 could not identify an equality operator for type point
#     '{…}'::line[]   = '{…}'::line[]   … for type line
#     '{…}'::path[]   = '{…}'::path[]   … for type path
#     ARRAY['<a/>'::xml] = same         … for type xml
#     ARRAY['{"a":1}'::json] = same     … for type json
#     '{a}'::text[]   = '{a}'::text[]   t                                  <- the control
#
# **The message names the element**, not the array. `min(lseg)` is the sharpest of the seven: the
# scalar `=` answers and the aggregate still does not exist, because an aggregate needs a btree
# family and equality alone is not one.
#
