# `json` and `jsonb`, as a real PostgreSQL 19beta1 answers them — tier 2, and the pair
# ([ADR 0033](../../../../docs/adr/0033-tier-1-of-the-type-surface.md)'s roadmap singles out:
# "jsonb's stored form, because it normalises key order and whitespace, so a capture decides what
# is stored rather than a preference"). `json` is OID 114 and `jsonb` is 3802, both varlena, both
# `typcategory` U. They are captured together because almost every fact below is a *difference*.
#
# Captured in one session with `scratchpad/sesscap.py` and replayed the same way against one node.
# It builds its own table, dropping whatever a previous run left, so a replay of `cut -f1` is
# byte-identical. The table is deliberately *not* dropped at the end: `sesscap.py` asks `\gdesc`
# for the declared types after the session closes, and a dropped table makes that column empty.
#
#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it
#   statement <tab> <tab> -               a command with no result set, only a tag
#   statement <tab> !SQLSTATE message     PostgreSQL refused it; DETAIL and HINT follow
#
# THINGS REASONING WOULD GET WRONG
#
#   * **`json` stores the text you sent, byte for byte.** Whitespace, key order and **duplicate
#     keys** all survive: `{"a":1,"a":2}` comes back exactly like that. `json` is a validated
#     string, and that is the whole of it.
#   * **`jsonb` stores a parsed value and prints a canonical one**, and the canonical form is not
#     the input: `{"b":1, "a":2}` becomes `{"a": 2, "b": 1}` — reordered, deduplicated (**last
#     key wins**), and with **a space after every colon and comma** that was not in the input.
#     An implementation that stored the text and sorted on read would still print the wrong
#     separators.
#   * **jsonb key order is by length first, then bytewise.** Measured twice:
#     `{"bb":1,"a":2,"ccc":3}` is `{"a": 2, "bb": 1, "ccc": 3}`, and `{"ab":1,"ba":2,"aa":3}` is
#     `{"aa": 3, "ab": 1, "ba": 2}`. Plain lexicographic ordering would put `ab` before `b`-
#     anything of any length and get the first one wrong.
#   * **A jsonb number is a `numeric`, so it carries `numeric`'s scale rule.** `1.00` stays `1.00`
#     and `1e2` becomes `100` — one is preserved and the other is not, because both are what
#     `numeric` does with that text. `1E400` becomes a four-hundred-digit integer in `jsonb` and
#     stays `1E400` in `json`. And **`'1.0'::jsonb = '1.00'::jsonb` is `t`** while the two print
#     differently: jsonb equality is numeric equality, not text equality.
#   * **`json` has no equality operator at all.** `'{"a":1}'::json = '{"a":1}'::json` is
#     `42883 operator does not exist: json = json`, and so is `@>`. Every operator below except
#     `->`, `->>`, `#>` and `#>>` is jsonb-only. So `json` cannot be a primary key, cannot be
#     `DISTINCT`ed and cannot be grouped, and that is a property of the type rather than a gap.
#   * **`jsonb` is ordered but has no `min`/`max`.** `<` works, `ORDER BY` works, and
#     `min(jsonb)` is `42883 function min(jsonb) does not exist` — the third time in this corpus
#     (`boolean`, `uuid`, `jsonb`) that a totally ordered type has no aggregate over it. The sort
#     order between *kinds* is its own fact: `true > 1` is `t` and `"s" > 1` is `f`.
#   * **`-> ` on a missing key is SQL NULL; `->` on a JSON null is JSON `null`.** `{"a":null} -> 'a'`
#     `IS NULL` is **`f`** and `->> 'a' IS NULL` is **`t`**. Two nulls, and only one of them is
#     SQL's. An out-of-range array index, and an object indexed by a number, are both SQL NULL
#     rather than errors.
#   * **`\u0000` splits the two types**, and it is the one input `jsonb` refuses that `json`
#     takes: `22P05 unsupported Unicode escape sequence` with `DETAIL: \u0000 cannot be converted
#     to text.` — a SQLSTATE that appears nowhere else here. `json` stores it, and casting that
#     stored `json` to `jsonb` raises the same error later.
#   * **Neither takes a typmod**, and the refusal is the *parser's*: `json(10)` is
#     `42601 syntax error at or near "("`, like `integer(4)` and unlike `uuid(10)`'s
#     `42601 type modifier is not allowed`.
#   * **Not captured, and deliberately: `jsonb_pretty`.** Its output is indented over several
#     lines, and `sesscap.py` drops any output row beginning with a space — so it would record a
#     silently truncated answer. Same class of trap as `pg19_varchar.txt`'s vanishing empty
#     string, recorded here so the next capture does not walk into it.
