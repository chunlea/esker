# `uuid`, as a real PostgreSQL 19beta1 answers it — tier 2
# ([ADR 0033](../../../../docs/adr/0033-tier-1-of-the-type-surface.md)'s roadmap). OID 2950,
# sixteen bytes fixed, `typcategory` U. `ActiveRecord`'s `t.uuid` and every `id: :uuid` primary
# key land here.
#
# Captured in one session with `scratchpad/sesscap.py` and replayed the same way against one node.
# It builds its own table, dropping whatever a previous run left, so a replay of `cut -f1` is
# byte-identical. The table is deliberately *not* dropped at the end: `sesscap.py` asks `\gdesc`
# for the declared types after the session closes, and a dropped table makes that column empty.
#
#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it
#   statement <tab> <tab> -               a command with no result set, only a tag
#   statement <tab> !SQLSTATE message     PostgreSQL refused it; DETAIL and HINT follow
#
# THINGS REASONING WOULD GET WRONG
#
#   * **`min(uuid)` and `max(uuid)` do not exist.** `42883 function min(uuid) does not exist` —
#     and yet `<`, `>`, `uuid_cmp` and `ORDER BY` all work, so the type has a total order and no
#     aggregate over it. Checked against `pg_proc` rather than inferred: no `min`/`max` takes 2950.
#     This is ADR 0031's `min(boolean)` finding a second time, and it is the reason that finding
#     was written down as a rule — **the aggregate set is per type and cannot be derived from
#     whether the type is ordered.** `count(uuid)` does exist; `sum` and `avg` do not.
#   * **Input is far more permissive than output.** All five of these are the same value —
#     hyphenated, upper case, **no hyphens at all**, wrapped in **braces**, and hyphenated in the
#     *wrong places* — and every one of them prints back as canonical lower-case hyphenated:
#     `a0eebc99-9c0b-4ef8-bb6d-6bb9bd380a11`. An implementation that validated the shape rather
#     than the sixteen bytes would reject four inputs a real server accepts.
#   * **But whitespace is not trimmed.** A single trailing space is `22P02`, where `'  integer  '`
#     is a fine `regtype`. Permissive about separators, strict about padding.
#   * **Every input failure is `22P02`**, with the offending string quoted — one message for a
#     wrong length, a wrong character, an empty string and an unbalanced brace alike. Unlike
#     `date` and `time`, there is no range error, because every sixteen-byte string is a `uuid`.
#   * **A typmod is refused, not ignored.** `uuid(10)` is
#     `42601 type modifier is not allowed for type "uuid"` — a fourth typmod error message, next
#     to `varchar`'s `22023`, `numeric`'s shouting `22023`, and `timestamp`'s silent clamp.
#   * **`uuid::bytea` is the sixteen raw bytes** (`\xa0eebc999c0b4ef8bb6d6bb9bd380a11`), and
#     `uuid::int` is `42846`. The value is bytes, never a number.
#   * **`gen_random_uuid()`, `uuidv4()` and `uuidv7()` are all built in** and need no extension.
#     They cannot be captured by value — what is pinned here is what is invariant about them.
