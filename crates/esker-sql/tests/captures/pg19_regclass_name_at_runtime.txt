# **A relation name reaches a `regclass` wherever the value does** — PostgreSQL 19beta1, 2026-09-09.
# `ON_ERROR_ROLLBACK on`, `BEGIN … ROLLBACK`.
#
# `debts-v1.1.md` #41, the half that needs a catalog. Three shapes, and the third is the one r1's
# run-110 wire gate found rather than the row:
#
#     INSERT INTO rh VALUES (1, 'ra')                    stores the relation
#     UPDATE rh SET r = 'rb'                             stores the relation
#     SELECT c::regclass FROM (VALUES ('pg_class')) s    answers `pg_class`, declared 2205
#
# The node answers `0A000 a relation name read as a regclass without a catalog` for the first two
# and `an oid is an integer, not Text("pg_class")` for the third — a value arriving somewhere its
# type was decided without it.
#
# ## THINGS REASONING WOULD GET WRONG
#
#   * **A comparison is the other way**, and that half is closed: `WHERE r = 'ra'` is `22P02`
#     because `=` is `oideq` (`tests/regclass_literal.rs`). Assignment resolves, comparison does not.
#   * **`IN` follows the assignment rule, not the comparison's**: `r IN ('ra','rb')` answers.
#   * **It is the relation and not the characters**: a value stored from a bare name follows a
#     later `ALTER TABLE … RENAME`, exactly as one stored from `'ra'::regclass` does.
#
# ## The measurements
#
