# `CREATE TEMPORARY TABLE` — a relation in a schema that belongs to one session (ADR 0053).
#
# **Run 56 stops exactly one test on it**, `UnloggedTablesTest#test_gracefully_handles_temporary_tables`,
# which asserts `pg_class.relpersistence` is `t`. The reason to build it is the other measure:
# `tests/relation_resolution.rs` asserts that **20 statements** of `pg19_relation_resolution.txt`
# are swallowed by the transaction this refusal aborts, so a third of that capture has never been
# compared with anything. That number falls to zero when this lands.
#
# Things reasoning would get wrong:
#
# * **A temp table is `relkind` `r` and `relpersistence` `t`.** It is a *table* — `table_exists?`
#   finds it — and what makes it temporary is the persistence column and the schema, not the kind.
# * **The search path does the whole of the shadowing**, and PostgreSQL's two spellings of it split
#   exactly where they need to: with a temp table the **implicit** path (`current_schemas(true)`) is
#   three long and starts with `pg_temp%`, and the **explicit** one (`current_schemas(false)`) is
#   one long and does not contain it. So a bare name finds the temp relation, `public.x` finds the
#   permanent one, and a table list — which filters `nspname = ANY (current_schemas(false))` — sees
#   neither the temp table nor its schema. There is no rule here that says "hide temp tables".
# * **`current_schema()` is still `public`.** The temp schema is first for *resolution* and is not
#   where an unqualified `CREATE TABLE` goes.
# * **A `serial` on a temp table makes a temp sequence, and an index on it is temp too** — both in
#   the temp schema, both `relpersistence` `t`. The property is inherited by everything the table
#   owns rather than being a property of the table alone.
# * **A permanent table may be created with the name a temp table already has.** They are in
#   different schemas, so `42P07` is only for a second *temp* table of that name.
# * **`ON COMMIT DELETE ROWS` fires on the implicit commit too.** A plain `INSERT` outside a
#   transaction block leaves **zero** rows behind, which is the fact this file exists to pin: an
#   implementation that only emptied the table at an explicit `COMMIT` would look right in a
#   transaction and lose every autocommitted row's visibility.
# * **`ON COMMIT DROP` outside a transaction block drops the table immediately**, for the same
#   reason.
# * **`ON COMMIT` on a permanent table is `42P16`**, and `CREATE TEMPORARY UNLOGGED TABLE` is a
#   **syntax error on a real server** — the two words cannot be combined, which is what
#   `UnloggedTablesTest` is checking that `ActiveRecord` never sends.
#
# The name of a temp schema carries the session's own number, so it is session state and can never
# be in a corpus. Every probe below asks `nspname LIKE 'pg_temp%'` instead.
#
# The first capture runs inside `BEGIN … ROLLBACK`; error probes sit in `SAVEPOINT`/`ROLLBACK TO`,
# and the `SELECT count(*)` after the `ROLLBACK` proves it left nothing behind.
#
# Rows start with a literal `'r'` because `sesscap.py` drops output rows that begin with a space.
