# 19beta1 answers them — in the order `ActiveRecord` hits them.
#

# and are captured already (`pg19_uuid.txt`, `pg19_interval.txt`, `pg19_regtype.txt`). These seven

#

#   741  GENERATED ALWAYS AS (expr) STORED

#   755  ALTER TABLE … ALTER COLUMN … SET DEFAULT

#
# **Statements are as `ActiveRecord` emits them**, taken verbatim from
# `triage/schema-probe-1a512ba-both.txt` rather than retyped — including the 1040-character
# `CREATE TABLE "defaults"` and the 522-character multi-statement `INHERITS` line.
#
# Captured in one session with `scratchpad/sesscap.py`, wrapped in **`BEGIN … ROLLBACK`**: this
# creates extensions, sequences, functions and triggers, and none of it may outlive the capture.
# Error probes sit in `SAVEPOINT` / `ROLLBACK TO` so one refusal does not abort the block. The two
# `SELECT count(*)` lines at the end prove nothing survived.
#
# A few `CREATE TABLE`s here are **scaffolding**, marked as such: `companies` has to exist before
# `ALTER TABLE companies ALTER COLUMN id …` can be asked, and in the suite `schema.rb` creates it.
#
#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it
#   statement <tab> <tab> -               a command with no result set, only a tag
#   statement <tab> !SQLSTATE message     PostgreSQL refused it; DETAIL and HINT follow
#
# As with `pg19_catalog_functions.txt`, the rollback means `\gdesc` — which runs in a second
# session afterwards — cannot describe the temporary objects, so those rows have an empty
# declared-types column. `pg_typeof` lines pin the types that matter.
#
# **A capture-tooling hazard this file found, and the reason for the three `DROP`s after the
# `ROLLBACK`.** `sesscap.py` fills the declared-types column by re-sending each statement with
# `\gdesc` appended, in a second session. For a single statement that is harmless — `\gdesc`
# describes without executing. For a **multi-statement line** it is not: psql executes every
# statement up to the last `;` and only describes the fragment after it, so the `INHERITS` line
# below — five statements in one message, as `ActiveRecord` sends it — was **executed for real,
# outside the `BEGIN`**, by the pass that was only supposed to be reading types. One pass left four
# objects on the oracle with the transaction's own `ROLLBACK` recorded as successful, which is how
# it was found: the capture was not idempotent and the counts inside the session said it should
# have been.
#
# So a capture containing a multi-statement line must clean up **after** its `ROLLBACK` as well as
# inside it. `pg19_ddl_cascade_fk_trigger.txt` has multi-statement `TRIGGER` lines and is worth
# re-checking against the same hazard.
#
# THINGS REASONING WOULD GET WRONG
#
#   * **`CREATE EXTENSION IF NOT EXISTS` on an already-installed extension is a plain success**,
#     not a no-op error and not a different tag — and it does **not** upgrade the version. The
#     second call below returns the same `pg_extension` row as the first.
#   * **A `GENERATED ALWAYS AS … STORED` column cannot be written**, and the refusal is its own
#     SQLSTATE: `428C9`, `cannot insert a non-DEFAULT value into column "virtual_stored_number"`,
#     with a `DETAIL` naming it a generated column. `DEFAULT` *is* accepted where a value is not —
#     the same asymmetry `GENERATED ALWAYS AS IDENTITY` has.
#   * **`attgenerated` is `s`**, and the expression lives where a default does not:
#     `pg_get_expr(adbin, adrelid)` on `pg_attrdef` returns the generation expression, while
#     `information_schema.columns.column_default` for that column is **NULL** — a generated column
#     has no default, and a reader that looked there would find nothing.
#   * **`OWNED BY` makes the sequence a dependent of the column, not of the table.** Dropping the
#     column drops the sequence; `DROP SEQUENCE` without `CASCADE` on a sequence a default depends
#     on is `2BP01`. And `START 101` means the **first** `nextval` is 101, not 102 — the start
#     value is returned, not stepped past.
#   * **`ALTER COLUMN … SET DEFAULT nextval(…)` replaces the `bigserial`'s own default** and leaves
#     the original sequence behind, still owned, which is why the suite drops
#     `companies_id_seq` on the next line. `pg_attrdef` shows one row for the column, the new one.
#   * **`DROP FUNCTION IF EXISTS f()` on a function that does not exist is a success**, and the
#     empty argument list is significant: `DROP FUNCTION IF EXISTS f` without parentheses is a
#     *different* statement (it means "any arity") and PostgreSQL 19 accepts it too. But once the
#     trigger below exists, the **same statement is `2BP01`** — `cannot drop function
#     partitioned_insert_trigger() because other objects depend on it`, with a `DETAIL` naming the
#     trigger. `IF EXISTS` covers absence, not dependency.
#   * **`INHERITS` arrives as five statements in one message**, dollar-quoted plpgsql included,
#     so it is all-or-nothing under the implicit transaction — the same rule
#     `pg19_ddl_cascade_fk_trigger.txt` measured for `DISABLE TRIGGER ALL`. The child table has
#     **no columns of its own**: `CREATE TABLE … ( ) INHERITS (parent)` takes the parent's, and
#     `pg_inherits` is where the relationship lives, not `pg_class`.
