# Arrays — `integer[]` and `text[]`, and `= ANY(...)` — as a real PostgreSQL 19beta1 answers them.
# Tier 2 ([ADR 0033](../../../../docs/adr/0033-tier-1-of-the-type-surface.md)'s roadmap names them
# last and says why they cannot wait: "`text[]` and `integer[]` columns *and* `= ANY($1)`, which
# `ActiveRecord` uses for every `IN` with binds — four of its 36 boot statements").
#
# `_int4` is OID 1007 and `_text` is 1009; both are `array_in`, `typdelim` `,`, `typcategory` A,
# and their `typelem` is the element type's OID (23 and 25). An array is not a new scalar — it is
# a *constructor over* one — which is why `'{2147483648}'::int[]` fails with `int4`'s own message.
#
# Captured in one session with `scratchpad/sesscap.py` and replayed the same way against one node.
# It builds its own table, dropping whatever a previous run left, so a replay of `cut -f1` is
# byte-identical. The table is deliberately *not* dropped at the end: `sesscap.py` asks `\gdesc`
# for the declared types after the session closes, and a dropped table makes that column empty.
#
#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it
#   statement <tab> <tab> -               a command with no result set, only a tag
#   statement <tab> !SQLSTATE message     PostgreSQL refused it; DETAIL and HINT follow
#
# THINGS REASONING WOULD GET WRONG
#
#   * **`= ANY` is three-valued and a match beats a NULL.** `1 = ANY('{NULL,1}')` is **`t`**;
#     `1 = ANY('{NULL,2}')` is **NULL**, not false; `NULL = ANY('{1,2}')` is NULL. So a NULL
#     element only matters when nothing matched. Over an **empty** array `= ANY` is `f` and
#     `= ALL` is `t`, and `1 = ANY(NULL::int[])` is NULL — three different empties.
#     This is the operator Rails puts every `IN (?)` through, so each of these is a row it can hit.
#   * **An empty array has no dimensions, so its length is NULL and its cardinality is 0.**
#     `array_length('{}', 1)` is NULL, `array_ndims('{}')` is NULL, `array_dims('{}')` is NULL,
#     and `cardinality('{}')` is **0**. A length of NULL where a caller expects 0 is the shape
#     that breaks a `LIMIT` computed from it.
#   * **An array containing NULL is not a NULL array.** `'{NULL}'::int[] IS NULL` is `f`, and
#     `array_agg` over one NULL row is `{NULL}` rather than NULL.
#   * **Subscripts are 1-based and out-of-range is NULL, never an error** — `[0]` and `[4]` on a
#     three-element array are both NULL. And a **two-dimensional array indexed with one
#     subscript is NULL**: `('{{1,2},{3,4}}')[1]` is NULL, not `{1,2}`. A slice is what returns
#     an array.
#   * **Lower bounds are part of the value and survive the round trip.** `'[0:2]={1,2,3}'::int[]`
#     prints back as `[0:2]={1,2,3}`, with `array_lower` 0. An implementation that stored only
#     the elements would print `{1,2,3}` and be wrong about the text.
#   * **Three shapes of malformed literal, three DETAILs, one SQLSTATE.** `22P02 malformed array
#     literal` with `Unexpected end of input.`, `Unexpected "," character.`,
#     `Unexpected "{" character.` and `Multidimensional arrays must have sub-arrays with matching
#     dimensions.` — but a bad *element* is not a malformed literal at all: `'{1,x}'::int[]` is
#     `22P02 invalid input syntax for type integer: "x"` and `'{2147483648}'::int[]` is
#     `22003 value "2147483648" is out of range for type integer`. The element type answers for
#     its own values.
#   * **`min` and `max` over an `integer[]` exist and return `integer[]`**, where over `uuid` and
#     `jsonb` they do not exist at all. `sum(integer[])` does not exist. A fourth per-type
#     aggregate answer in this corpus, and the fourth reason not to derive the set from the
#     category.
#   * **Comparison is element-wise then by length**: `'{2,1}' = '{1,2}'` is `f` — order matters —
#     and `'{1,2}' < '{1,2,3}'` is `t`. `@>` over an empty right side is `t`; over a NULL array it
#     is NULL.
#   * **Unquoted `NULL` inside a literal is a NULL and quoted `"NULL"` is the string**, and
#     unquoted whitespace around elements is trimmed (`'{ a , b }'` is `{a,b}`) while quoted
#     whitespace is kept. Output re-quotes only what needs it: `{a,b}` but `{"a b","c,d"}`.
#   * **Backslash escaping inside a quoted element is the element's, not SQL's**, and the three
#     lines here pin the whole rule. With `standard_conforming_strings` on, `'{"a\"b"}'` reaches
#     `array_in` as `{"a\"b"}`: the `\"` is an **escaped quote**, the element is `a"b`, and it
#     prints back re-escaped as `{"a\"b"}`. `'{"a\\b"}'` is an escaped **backslash** and round
#     trips the same way. But `'{"a\\"b"}'` — an escaped backslash *then* a quote — closes the
#     element early and is `22P02 malformed array literal` with a fourth DETAIL,
#     `Incorrectly quoted array element.` One character apart, and one of them is an error.
#   * **`ARRAY[]` with no cast is an error**, `42P18 cannot determine type of empty array`, with a
#     HINT naming the fix. `'{}'::int[]` is fine — the cast is the type, not the contents.
#   * **Not captured, and measured anyway: the bind form.** `PREPARE p(int[]) AS SELECT ... WHERE
#     id = ANY($1)` then `EXECUTE p('{1,3}')` returns rows 1 and 3; `EXECUTE p('{}')` and
#     `EXECUTE p(NULL)` return none. Those are not lines below because `sesscap.py` fills the
#     declared-types column by asking `\gdesc` in a *second* session, which has no such prepared
#     statement — an `EXECUTE` can only ever be captured with that column empty. The semantics it
#     tests are the `= ANY` lines that are here.
