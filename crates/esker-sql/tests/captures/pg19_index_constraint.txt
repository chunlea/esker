# Index and constraint shapes, as a real PostgreSQL 19beta1 answers them.
#
# NOT a type. These are items 4, 7 and 8 of `triage/blockers-51390c9.md` — the **tail of the schema
# gate**: after `json`, `current_schemas`, `date`, `numeric` and `float`, seven statements of
# `activerecord/test/schema/schema.rb` are still refused and every one of them is an index shape,
# a foreign key or a volatile default. Captured now so that unit has its oracle before it starts,
# rather than after.
#
# Captured in one session with `scratchpad/sesscap.py` and replayed the same way against one node.
# It builds its own tables, dropping whatever a previous run left. They are deliberately not
# dropped at the end: `sesscap.py` asks `\gdesc` for the declared types in a *second* session, and
# a dropped table makes that column empty.
#
#   statement <tab> types <tab> rows      the result, and the types `\gdesc` declared for it
#   statement <tab> <tab> -               a command with no result set, only a tag
#   statement <tab> !SQLSTATE message     PostgreSQL refused it; DETAIL and HINT follow
#
# THINGS REASONING WOULD GET WRONG
#
#   * **The stored index definition keeps only what differs from the default, and the default
#     depends on the direction.** `(a ASC NULLS FIRST)` comes back as **`(a NULLS FIRST)`** — the
#     `ASC` is dropped because it is the default, and the `NULLS FIRST` is kept because ASC's
#     default is NULLS **LAST**. `(a DESC NULLS LAST)` keeps **both**, for the mirror reason. So
#     an implementation cannot round-trip the text it was given; it has to store direction and
#     null-placement and re-derive the shortest spelling.
#   * **`NULLS NOT DISTINCT` is a column of `pg_index`, not part of the key.**
#     `indnullsnotdistinct` is `t` for it and `f` for the default, and the clause prints **after**
#     the column list: `... USING btree (c) NULLS NOT DISTINCT`. Writing `NULLS DISTINCT`
#     explicitly stores and prints nothing — it is the default.
#   * **A partial predicate is re-printed normalised and parenthesised**: `WHERE published_on IS
#     NOT NULL` comes back `WHERE (published_on IS NOT NULL)`, and an expression index written
#     `((lower(b)))` comes back `(lower(b))` — one layer of parentheses removed. Two opposite
#     rewrites in one statement.
#   * **A bad column in the *predicate* is the same error as a bad column in the key**:
#     `42703 column "nosuchcol" does not exist` for both. A duplicate index name is `42P07`, the
#     same code a duplicate table gets.
#   * **`pg_get_constraintdef` drops `INITIALLY IMMEDIATE` and keeps `DEFERRABLE`**, because
#     `INITIALLY IMMEDIATE` is the default — so the exact clause `ActiveRecord` writes,
#     `DEFERRABLE INITIALLY IMMEDIATE`, is *not* what comes back out. `condeferrable` is `t` and
#     `condeferred` is `f`, which is the pair that says so.
#   * **PostgreSQL 19 has a `pg_constraint` row for `NOT NULL`**, `contype` `n`, named
#     `<table>_<column>_not_null` — a row that did not exist in older majors and that a catalog
#     emulation copied from an older memory would be missing.
#   * **A foreign key violation is `23503` with two different sentences**: inserting a child says
#     `insert or update on table "ixc" violates ...` with `Key (p)=(99) is not present`; deleting
#     the parent says `update or delete on table "ixp" violates ... on table "ixc"` with
#     `Key (id)=(1) is still referenced`. One code, two messages, and the second names both tables.
#   * **A volatile default is stored as its own text, unparenthesised, where a computed one is
#     parenthesised.** `CURRENT_TIMESTAMP` and `CURRENT_DATE` come back exactly as written;
#     `DEFAULT 1 + 1` comes back `(1 + 1)`. And an unknown function in a default is `42883` with
#     `DETAIL: There is no function of that name.` — *not* the usual "No function of that name
#     accepts the given argument types."
#   * **The `CASE` expression index — captured after all, by normalising the newlines in the
#     statement.** `pg_get_indexdef` renders a `CASE` over several indented lines and `sesscap.py`
#     drops output rows beginning with a space, so the raw call cannot be a line here. Wrapping it
#     in `regexp_replace(…, '\s+', ' ', 'g')` collapses it to one line and makes it capturable —
#     and the comparison line below proves the normalisation is a **no-op for every other index**
#     (`= pg_get_indexdef(...)` is `t` for the mixed index and `f` only for the `CASE` one), so the
#     rewrite hides nothing.
#
#     Two facts it turned up that the prose note could not:
#
#     **`pg_get_indexdef` materialises the implicit `ELSE`.** Written
#     `(CASE WHEN rating > 0 THEN lower(name) END)`, it comes back as
#     `CASE WHEN (rating > 0) THEN lower(name) ELSE NULL::text END` — the omitted branch is filled
#     in *with its resolved type*, and the condition gains parentheses. So the stored text is not
#     the written text even after whitespace is normalised.
#
#     **An expression index column is `indkey` 0.** Zero means "not a column, see `indexprs`", and
#     `indnatts` still counts it as one attribute.
#
#   * **An expression index column needs its own parentheses.**
#     `ON cx ((CASE … END))` is accepted and `ON cx (CASE … END)` is
#     `42601 syntax error at or near "CASE"`. The doubled parenthesis is grammar, not style — and
#     one layer of it is removed on the way back out: `((lower(name)))` prints as `(lower(name))`.
