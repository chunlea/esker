# **A stored `regclass` holds its number and resolves its name on the way out** — PostgreSQL
# 19beta1, 2026-09-09. `ON_ERROR_ROLLBACK on`, one `BEGIN … ROLLBACK`, fixture in the first two
# statements.
#
# `debts-v1.1.md` #35. The row this closes said a `regclass` could not be a stored column here,
# and the reason was the row shape: this node's `Datum::RegClass` carries the printed name beside
# the oid, so storing one would write the name into the row — and a name in a row goes stale.
#
# ## THINGS REASONING WOULD GET WRONG
#
#   * **`ALTER TABLE … RENAME` changes what an *already stored* value prints.** The row is not
#     rewritten and nothing reconciles it: `r` is the same eight bytes before and after, and it
#     prints `rc_a` then `rc_b`. That is the measurement that says the name is not in the row.
#
#   * **Dropping the relation does not NULL the value and does not raise.** The column keeps its
#     number and prints the **digits** — `r IS NULL` is `f`, and `r::text = r::oid::text` is `t`.
#     So "unresolved" is a real server's own rendering, not a placeholder to be avoided: a reader
#     with no catalog to ask degrades to exactly this.
#
#   * **`'nosuchrel'::regclass` fails at the cast, before any row is written** — `42P01`, the same
#     refusal the bare expression gives. The column never sees a name.
#
#   * **A `regclass` is a primary key**, and an index over one is ordinary.
#
# ## The measurements
#
