# The catalog lives in `pg_catalog` — the namespace unit the `relkind` divergence argued for.
#
# **Run 56: `schema_cache_test.rb` 7 tests on `relation "pg_type" does not exist`, and
# `postgresql_adapter_test.rb` 2 on `relation "pg_catalog.pg_class" does not exist`.** Two
# statements, both from `ActiveRecord`'s own adapter and both verbatim below:
#
#   * `postgresql/schema_statements.rb:436`, `primary_keys` — `i.indrelid = '"pg_type"'::regclass`.
#     The name arrives **quoted**, because `quote_table_name` put it there, and a catalog relation
#     was resolved by its bare spelling only.
#   * `postgresql/schema_statements.rb:188`, `table_comment` — `FROM pg_catalog.pg_class c LEFT
#     JOIN pg_namespace n ON n.oid = c.relnamespace … AND n.nspname = 'public'`. The qualifier is
#     the relation's real schema, and the join is what a client uses to keep the catalog out of a
#     schema dump.
#
# Things reasoning would get wrong:
#
# * **A catalog relation's `relkind` is `r`, not `v`** — `pg_class`, `pg_type` and twenty others
#   are ordinary tables. Only five are views: `pg_indexes`, `pg_views`, `pg_stat_activity`,
#   `pg_available_extensions`, and every `information_schema` relation. A node that answered `v`
#   for all of them kept them out of `ActiveRecord`'s `tables()` by accident, and this file is why
#   that accident can be given up: the namespace does it properly.
# * **`nspname = ANY (current_schemas(false))` is what excludes them**, and `current_schemas(false)`
#   is `{public}` while `current_schemas(true)` is `{pg_catalog,public}`. So the catalog is
#   *resolvable* without a qualifier and *invisible* to a table list, which are two different
#   questions answered by two different functions.
# * **A `regclass` prints qualified exactly when its schema is not in the search path.**
#   `to_regclass('pg_catalog.pg_class')::text` is `pg_class` and
#   `to_regclass('information_schema.tables')::text` is `information_schema.tables`, in one row of
#   one statement. An implementation that always printed the bare name, or always the qualified
#   one, gets one of the two wrong.
# * **`information_schema.tables` *does* list `pg_class`.** It is every schema's relations, not the
#   search path's, so the two catalog names are in it — which is why `ActiveRecord` reads
#   `pg_class` joined to `pg_namespace` for `tables()` and not this view.
# * **`SELECT … FROM public.pg_class` is `42P01`**, quoted whole as `"public.pg_class"`: the
#   catalog is not in `public`, and a qualifier that names the wrong schema finds nothing even
#   when the bare name would have found something.
# * **`CREATE TABLE pg_catalog.mine` is `42501`, not `42P07` or `0A000`**, and its own sentence:
#   `permission denied to create "pg_catalog.mine"` with `DETAIL: System catalog modifications are
#   currently disallowed.`
# * **`pg_attribute` has a row per column of every catalog relation**, `pg_views`' four included.
#   The whole file's column lists are a real server's; this node models a subset of the wide ones,
#   which is where its declared divergences are.
#
# The capture runs inside `BEGIN … ROLLBACK`; error probes sit in `SAVEPOINT`/`ROLLBACK TO`, and
# the `SELECT count(*)` after the `ROLLBACK` proves it left nothing behind.
#
