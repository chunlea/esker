# **The integer bitwise operators** — PostgreSQL 19beta1, 2026-09-08. One `BEGIN … ROLLBACK`.
#
# `connection_test.rb#test_get_and_release_advisory_lock` builds its key the way `ActiveRecord`
# builds every advisory-lock key — `(a::bigint << 32) | b::bigint` — and this node answered
# `the operator | is not supported`.
#
# ## What reasoning gets wrong
#
#   * **A shift keeps its LEFT operand's type**, where the other four take the wider of the two:
#     `1::int2 << 4` is a `smallint` and `12::int2 | 10::int4` is an `integer`.
#   * **A shift count is taken modulo the width.** `1::int4 << 32` is **1**, `1::int8 << 64` is 1,
#     and `1::int4 << -1` is `-2147483648`, which is `1 << 31`. Nothing overflows and nothing is
#     refused — the count wraps, which is the hardware showing through.
#   * **`>>` is arithmetic**: `(-1) >> 1` is `-1`.
#   * **`&` binds tighter than `|`**, and `<<` tighter than both: `2 | 3 & 1` is 1, `1 << 2 | 1`
#     is 5.
#   * **`^` is exponentiation in this dialect and `#` is the XOR** — the one pairing a reader
#     coming from C has backwards.
#   * Two unknown literals are **`42725 operator is not unique`**, not the `42883` a wrong type
#     gets: every integer width offers a candidate and none of them wins.
#
# The rows below are the measurement, in corpus form.
#
