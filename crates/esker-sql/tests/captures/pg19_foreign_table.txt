#
# **This file is an ADR 0031 contract violation, not a ranking row.** Run 47 found
# `foreign_table_test.rb` answering ten `DROP SERVER`s with the parser's expected-token list; run 50
# found its neighbour doing the same — `syntax error: sql parser error: Expected: COLLATION,
# CONNECTOR, DATABASE, EXTENSION, FUNCTION, INDEX, OPERATOR, POLICY, PROCEDURE, ROLE, SCHEMA,
# SECRET, SEQUENCE, …`, 10 raises. C2 requires a refusal that **names the feature**; a token list is
# category (a), the one class the contract forbids outright. Neither run's raises appear in any
# ranking row, because each of those tests had already been counted on the
# `extension "postgres_fdw" is not available` its `setup` raised first. So this capture is here to
# say what the four statements are and what a real server answers, so the refusal can name them.
#
# The four, from `foreign_table_test.rb:22-44` and `:47-50`, with the test's own arguments:
#
#     CREATE SERVER foreign_server FOREIGN DATA WRAPPER postgres_fdw OPTIONS (dbname '<arunit2>')
#     CREATE USER MAPPING FOR CURRENT_USER SERVER foreign_server
#     CREATE FOREIGN TABLE foreign_professors (id int, name character varying NOT NULL)
#       SERVER foreign_server OPTIONS (table_name 'professors')
#     DROP SERVER IF EXISTS foreign_server CASCADE
#
# Things reasoning would get wrong:
#
# * **A foreign table is a data source but not a table.** `test_table_exists` asserts
#   `table_exists?` is **false** for one while `data_source_exists?` is **true**, and that is one
#   `relkind` letter: AR maps `BASE TABLE` to `'r','p'`, `VIEW` to `'v','m'` and `FOREIGN TABLE` to
#   `'f'` (`postgresql/schema_statements.rb:1171-1176`). Answering `f` as `r` passes the wrong test.
# * **`CREATE SERVER` validates nothing.** The database named in `OPTIONS (dbname …)` need not exist
#   — no connection is made until something reads the foreign table, and *that* is where the error
#   comes from. The rows below show both: a server pointing at a database that does not exist is
#   created happily, and the `SELECT` through it is what fails.
# * **A foreign table's columns are its own declaration**, not the remote's. They live in
#   `pg_attribute` like any other relation; the mapping to the remote is `pg_foreign_table.ftoptions`.
# * **`DROP SERVER … CASCADE` takes the user mapping and every foreign table with it**, which is why
#   the test's teardown is one statement. Both are dependencies and both refuse a bare `DROP SERVER`
#   with `2BP01`: dropping the foreign table is **not** enough, the user mapping holds it too. The
#   rows below take them off one at a time to show it.
# * **Nothing connects until something reads.** The loopback probe below fails at `SELECT` time with
#   `08001`, naming the role the wrapper tried — the server and the mapping were both created
#   without complaint. That is the fact the probe is here for; which role a container happens to
#   accept is not. The `NOTICE`/`DETAIL` a cascade prints is described here
#   rather than captured, because `sesscap.py` records continuation lines with no prefix in the rows
#   column.
#
# The whole capture runs inside `BEGIN … ROLLBACK` — `CREATE SERVER`, `CREATE USER MAPPING` and
# `CREATE FOREIGN TABLE` are all transactional — and the `SELECT count(*)` lines after the
# `ROLLBACK` prove it left nothing behind.
#
